### 为何做
D11 已打通 mainnet 首笔 bundle（0302a15a confirmed），但 `jito_bundle_demo.py` 是「写死 tip + 无日志」的一次性脚本。D12 目标是把它升级成可复用管线，为 D13「bundle 加套利逻辑」铺路：tip 必须动态定价（实测 tip_floor 2 分钟内从 0.0009 涨到 0.0035 SOL，写死必失效）。

### 怎么做
新建 `scripts/jito_bundle_pipeline.py`（保留 demo 作为最小参考）：
1. **tip 自动定价**：现场查 `bundles.jito.wtf/api/v1/bundles/tip_floor`，默认 99 分位 ×1.5 安全垫，下限 0.003 SOL / 上限 0.01 SOL（防极端行情烧钱）；`--tip-mode fixed` 可手工指定

3. **状态机轮询**：`getBundleStatuses` 主查 + `getInflightBundleStatuses` 兜底（能拿到 Invalid 明细），landed/pending/invalid 三态区分
4. 参数化：`--network mainnet|testnet` / `--n-tx 1~5` / `--dry-run`

### 结果
- dry-run 全绿：auto 定价（99th=0.00428 → 0.0064 SOL）、fixed 模式、testnet、n_tx=1 纯 tip 单笔 ✅
- 4 条测试日志已写入 JSONL ✅
- 关键发现：tip_floor 是**动态**的（2 分钟内 99th 0.0009→0.0035 SOL），写死 tip 的 demo 只适用于当时市场——这也是为什么 demo 用 0.005 SOL 恰好成功、现在 auto 定价才是正确形态

### 为何做

### 怎么做（第一轮 9a904ea5 → Invalid）
1. 首提 3 tx（2 self-transfer + tip 0.003 SOL）→ sendBundle 返回 **HTTP 400**！
2. curl 重放看错误 body：`Duplicate transaction message hash detected`——两笔 self-transfer 的 from/to/金额/blockhash 全相同 → **message 相同 → 签名相同 → block engine 拒收**（D11 第 8 轮纯 tip 单笔恰好绕开了此坑）
3. 修复：self-transfer 金额×序号递增（1000/2000/3000…）+ http_post 捕获 HTTPError 读 body（urllib 默认丢错误 body）
4. 重提 → 拿到 bundle_id 但 12 次轮询全 `?`——**inflight 字段读错**：`getInflightBundleStatuses` 返回的是 `status`（Pending/Landed/Invalid）不是 `confirmation_status`；实际状态 = Invalid（tip 0.003 仍不够）
5. 修轮询字段 + auto 定价下限 0.003 → 0.005（D11 实测 0.005 稳）

### 结果（第二轮 55ed86fb → ✅ confirmed）
- bundle_id `55ed86fbd4b38c1f338d5e9b0f9570e353001e5ed8fdea52c05071c878679e96`，confirmation_status=confirmed，err={'Ok': None}，slot 439560007，提交后 ~7 秒落地
- 链上对账：钱包 0.181129255 → 0.176124255 SOL（-0.005005 = tip 0.005 + 手续费 5000）✅
- JSONL 日志 3 条完整（dry-run → timeout-pending → landed），全程可追溯
- 意外发现：tip_floor 99 分位波动极大（同一小时内 0.000029 → 0.0035 → 0.008 SOL），且是「已落地 bundle」滞后统计——**不能只信分位数，必须有下限**；实测下限 0.005 SOL 稳

### 意义
管线 v2 实战闭环 + 两个新坑沉淀（duplicate message hash / inflight 字段名）+ 第三条落地证据。**Jito bundle 提交管线达到「可复跑、可审计、有定价逻辑」状态**，D13 直接挂模拟器输出路径即可。D11 的「8 轮排查方法论」正式沉淀成可复用工程：tip 定价从「拍脑袋 0.005」变成「查分位×安全垫+实测下限」，每次提交都有日志审计。
