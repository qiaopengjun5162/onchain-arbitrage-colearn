# 2026-08-16 每日打卡（Day 12）

## 主线：Jito bundle demo → 参数化管线升级

### 为何做
D11 已打通 mainnet 首笔 bundle（0302a15a confirmed），但 `jito_bundle_demo.py` 是「写死 tip + 无日志」的一次性脚本。D12 目标是把它升级成可复用管线，为 D13「bundle 加套利逻辑」铺路：tip 必须动态定价（实测 tip_floor 2 分钟内从 0.0009 涨到 0.0035 SOL，写死必失效）。

### 怎么做
新建 `scripts/jito_bundle_pipeline.py`（保留 demo 作为最小参考）：
1. **tip 自动定价**：现场查 `bundles.jito.wtf/api/v1/bundles/tip_floor`，默认 99 分位 ×1.5 安全垫，下限 0.003 SOL / 上限 0.01 SOL（防极端行情烧钱）；`--tip-mode fixed` 可手工指定
2. **结构化日志**：每次运行 append JSONL 到 `data/jito_bundle_log.jsonl`（ts/network/n_tx/tip/basis/bundle_id/status/err），构造-提交-落地全程可追溯
3. **状态机轮询**：`getBundleStatuses` 主查 + `getInflightBundleStatuses` 兜底（能拿到 Invalid 明细），landed/pending/invalid 三态区分
4. 参数化：`--network mainnet|testnet` / `--n-tx 1~5` / `--dry-run`

### 结果
- dry-run 全绿：auto 定价（99th=0.00428 → 0.0064 SOL）、fixed 模式、testnet、n_tx=1 纯 tip 单笔 ✅
- 4 条测试日志已写入 JSONL ✅
- 关键发现：tip_floor 是**动态**的（2 分钟内 99th 0.0009→0.0035 SOL），写死 tip 的 demo 只适用于当时市场——这也是为什么 demo 用 0.005 SOL 恰好成功、现在 auto 定价才是正确形态

### 意义
D11 的「8 轮排查方法论」沉淀成可复用工程：tip 定价从「拍脑袋 0.005」变成「查分位×安全垫」，每次提交都有日志审计。D13 只需把 demo transfer 换成模拟器输出的 swap 路径即可进入套利逻辑阶段。
