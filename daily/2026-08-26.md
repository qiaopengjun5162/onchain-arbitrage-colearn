## 主线：高频偏离轮询原型（30min cron → 2-3s/tick）

**为什么做**：v1 prey radar 是 30min cron 全市场扫描，实测跑一次 >180s 超时（200 市场串行 ≈720s）——30min 粒度对清算窗口（秒~分钟级）毫无意义。08-25 daily 已定信号链修正：不监听预言机交易，改高频轮询「现货 vs oracle 偏离」→ 偏离突变 = 预言机即将更新 = 清算窗口临近。

**怎么做**（四个实测关键）：
1. **JSON-RPC 批量 eth_call 可用**（publicnode 2.2s/批）——1 次请求拿全部 oracle price()。此前误判「不支持批量」= 拿代币地址调 price() 会 revert，不是批量问题
2. **DeFiLlama 批量多币种 >10 币单请求返回空**（9 币 1.9s 正常）→ 分块 ≤8
3. **checksum 坑**：DeFiLlama key 全小写 vs GraphQL checksum 地址 → 不统一小写全 cache miss（WETH 天然小写才侥幸命中）
4. watchlist 默认 top-12 活跃市场（按 supply），每 tick = 1 次批量 RPC + 1 次批量 DeFiLlama（现货 5s 缓存）

**结果**（全部实测）：
- `--once` 单次快照 9.7s：11/12 市场解析成功；活跃市场全部 ok（偏离 <25bps），mGLO −638bps（oracle 落后偏安全，与 v1 一致）；**当前无埋雷**
- 45s 高频实测：降采样 22 条（vs 全量 540，降 96%）；安静期漂移仅 **−1.7~+1.7bps**/tick，零误报；有效节奏 ~2.2-2.5s/tick
- 信号方向语义确认：`dev_bps = (oracle−spot)/oracle`，**正值 = oracle 高估 = 危险方向**（下修 → 清算窗口）

**已知限制**：cbBTC→EURC 类 EUR 报价预言机未解析（需 EUR/USD 交叉汇率）；节奏受公共 RPC 限制（Flashblocks WS 到位后才 <200ms）；DeFiLlama 现货延迟 ~5-7s；未接 HF scanner 联动。

**意义**：清算事件线从「30min 级哨兵」升级到「2-3s 级雷达」——偏离突变检测（Δ≥20bps/tick）是预言机更新的前置信号，这是结营后主攻方向 #1 的执行基建第一块。下一环：挂 cron 窗口报警 → Flashblocks WS → HF scanner 联动。
