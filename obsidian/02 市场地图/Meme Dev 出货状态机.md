# Meme Dev 出货状态机

> 来源：@hunterweb303 推文 + Pons 土狗盘 Dev 链上取证（35 盘 + 105 盘两轮，Swap/转账/分润回执逐笔核）。
> 定位：信息差套利的状态机案例——**不预测 K 线，只判断「Dev 还在做盘还是已开始兑现」**，在受控大出货前进出。

## Dev 出货状态机（可复用动作序列）

| 阶段 | 动作 | 链上痕迹 |
|---|---|---|
| 1. 建仓 | 每盘先拿 ~3.8 ETH 建初始仓，不追买 | 主地址大额买入 |
| 2. 藏仓 | ~59% 库存转入子钱包 | 主→子转账（只盯发币钱包看不到） |
| 3. 试探 | 小卖 0.4%~1% 库存看买盘接不接 | 小额卖出簇 |
| 4. 主卖 | 盘子从高点回落后卖 ~40% 初始库存 | 大额卖出簇（26/28 盘对上） |
| 5. 子钱包清仓 | 主卖后清那 ~59% 库存 | 子地址卖出簇（23/25 盘对上） |
| 6. 分润 | Locker 分润回执（31/35 盘出现） | 分润转账 |

**关键认知**：出货不是一根大阴线，而是主/子/残余清理分段释放。币价跌了 ≠ Dev 亏了（他有初始库存+已卖库存+子钱包库存+交易费四本账）。

## 「四本账」监控（可工程化的哨兵指标）

1. 主地址+直接转仓地址还压着多少库存
2. 当前价格离这张盘自身前高多远
3. 最近 5/20/100 区块外部买卖净流和笔数变化
4. 最近一次受控动作（建仓/试探/主卖）是什么、距今多久

## 进出规则（风险边界）

- **进场**：费后（池费+Gas+滑点）为正才进，每笔成交重新报价
- **退出**：①费后正数就走；②受控大卖开始出现就走；③退出报价被吃掉也走
- **不要当固定公式**：Dev 参数会换版本（「外部买入>0.10 ETH 先分仓」最后 32 盘只中 13 次）——可自动化 ≠ 永远同一套参数

## 与知识库互证

- 信息差套利三步法同构：赚钱=信息差套利，本文是「Dev 状态」这个信息差的完整取证样例
- 主钱包→子钱包→分润地址图谱 = 链上取证横纵分析法应用（0xd712/888BMM 手法搬到 meme Dev）
- 哨兵架构同构：四本账 = 4 个监控指标，与无套利带雷达同一套「只读发现，人扣扳机」模式
