## ① Qi8888btc — Hook 池套利科普（"撞 Hook 池"）

**来源**：https://x.com/Qi8888btc/status/2092240519640514583（08-25 13:19 UTC，102 likes 待核验页）

**内容**：
- 核心转变：以前找「池子之间的价差」→ 现在找「**Hook 规则本身的价差**」
- Hook = 嵌在池内的可编程交易规则（动态手续费/返利/Custom Accounting/Oracle/竞价/利润分配），决定套利交易如何结算；设计正常的套利分成型 Hook = 把套利者拿走的价差截一部分分给 LP/协议
- 新玩法「**撞 Hook 池**」：小资金撞不同 Hook 池，通过不同金额 Swap 观察手续费/返利/结算结果 → 推断利润分配规则 → 找参数不合理（LP 分成 0 / 奖励曲线异常）的池子 → 找最优交易金额吃超额
- 案例：某 HOOK 池 LP 分成比例设为 0，给了很大套利机会
- 原文自评：门槛高，了解为主

**核验对照**：
- 与 08-25 六连发① `group-share-six-links-20260825.md`（Bruce v4 Hook 恶意池机制深挖）**同主题热度延续**：我们已有恶意池检测（gas 环境区分模拟/执行=报价核验第 4 指纹）、Hook 机制拆解
- **新增角度**：「主动撞池探测参数」= 主动侦察 vs 被动扫描——与我们 prey radar「撞预言机」思路同族（用小资金探测协议参数错配）；LP 分成 0 案例 = 参数错配型机会（同 08-24 Bruce 系列「机制性漏洞」家族）
- 无 tx hash/无收益数字 = 叙事科普帖，机制可学、数字无可核验

**判定**：了解为主归档；Hook 参数错配探测列入研究线备选（与恶意池检测共享基建），门槛高不优先。可执行：无新工具需求（我们的 eth_call/GraphQL 侦查栈可直接探测 Base 上 Hook 池）
