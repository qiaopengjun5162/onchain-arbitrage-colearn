# 公共模型与统一计算规则

本篇统一六种模型计算盈亏、记录库存、处理交易状态和进行回测的方法。各模型只补充自身特有风险。

## 1. 标准库存模型

以 WETH/USDC 为例：

```text
便宜链：USDC -> +Q WETH
贵链：  -Q WETH -> USDC
```

两条腿均成功时，全局 WETH 近似不变，只是库存换了链；稳定币增量才是毛套利收益。手续费以 ETH/WETH 支付、成交量不一致或部分成交时，仍会残留 WETH 变化。

## 2. 统一盈亏公式

### 单次机会

```text
grossSpreadUsd = sellProceedsUsd - buyCostUsd

netArbitragePnlUsd
= grossSpreadUsd
- buyGasUsd - sellGasUsd - tradingFeesUsd
- expectedRebalanceCostUsd
- hedgeCostUsd
- failureLossReserveUsd
```

直白地说：单次净利 = 卖出收到的钱 − 买入花的钱 − 两边网络手续费 − 交易费 − 预计补库存成本 − 反向保护成本 − 失败损失准备金。

发现机会时必须使用可执行数量和 `toAmountMin`；展示价格或 `toAmount` 只能用于观察。

### 整体组合

```text
totalPnlUsd
= netArbitragePnlUsd
+ inventoryMarkToMarketUsd
+ hedgePnlUsd
- fundingOrBorrowCostUsd
- liquidationLossUsd
- operationalLossUsd
```

直白地说：策略总盈亏不仅包括套利净利，还要加上库存涨跌和对冲盈亏，再减去借款、强制平仓和操作错误造成的损失。

“价差赚钱”不等于整个策略赚钱。没有做反向保护的 ETH 库存，其价格涨跌常常大于单次套利收益。

## 3. 统一风险表

| 风险 | 典型触发 | 直接损失 |
|---|---|---|
| 市场方向 | ETH/WETH 涨跌 | 库存减值、债务升值，或表现落后于单纯持有 |
| 买卖只成功一笔 | 买入成功但卖出失败，或卖出成功但买入失败 | 意外持有过多或过少资产；补做失败的交易时承担滑点和额外网络手续费 |
| 报价失效 | 报价、模拟、签名到上链期间价格变化 | 交易失败但仍支付网络手续费，或者成交价格变差 |
| 流动性 | 资金池深度下降、大额交易影响价格 | 价格变差、无法补做失败的另一笔交易 |
| 抢跑和插队（MEV） | 交易公开等待打包、允许价格变化范围过宽 | 被抢先、夹击或跟随交易，利润被别人拿走 |
| 网络手续费（Gas） | 网络拥堵、估算错误、交易序号阻塞 | 毛利被吞噬或交易卡住 |
| 补库存 | 桥接延迟、失败、部分完成 | 资金闲置、库存未恢复、收到中间代币 |
| 协议 | DEX、桥、借贷、永续或合约漏洞 | 部分至全部本金损失 |
| 链与基础设施 | 交易排序器、节点接口（RPC）、链重组或暂停 | 无法交易、提取或正确判断状态 |
| 资产 | 假代币、包装资产、冻结、脱锚 | 无法兑换或价值突然下跌 |
| 操作与系统 | 私钥、交易序号、金额精度、地址或配置错误 | 错链、错金额、重复发送、错误授权 |
| 模型 | 数据缺失、回测偷看未来或只保留成功项目 | 回测盈利、真实交易亏损 |

## 4. 买入和卖出只有一笔成功

不同链上的两笔交易不是一个原子事务：

| 情况 | 结果 | 主要损失 |
|---|---|---|
| 买入成功、卖出失败 | WETH 增加，价格下跌会亏损 | 补卖时价格下跌、滑点、额外网络手续费 |
| 卖出成功、买入失败 | WETH 减少，价格上涨会少赚或亏损 | 补买时价格上涨、滑点、额外网络手续费 |

```text
executionMismatchLoss
= abs(unmatchedAssetAmount) * adversePriceMove
+ emergencyTradeSlippage
+ emergencyGas
```

交易程序必须定义：最大未匹配数量、最多允许暴露多久、紧急交易的滑点上限，以及第一次补做失败后还能走哪条备用路径。

## 5. 跨链状态

不能只检查交易是否 `DONE`：

| 状态 | 含义 | 库存处理 |
|---|---|---|
| `DONE + COMPLETED` | 收到预期资产 | 核对地址、数量和确认数后转为可用 |
| `DONE + PARTIAL` | 收到中间资产，而非目标代币 | 隔离并进入恢复流程 |
| `DONE + REFUNDED` | 未完成，资产已退款 | 按真实退款链、代币和数量入账 |
| `FAILED` | 失败，可能需要人工或桥侧退款 | 保持在途，直至资产去向确认 |

`PARTIAL` 可能看起来钱还在，却没有得到下一轮需要的代币。回测与真实交易都必须按实际所在链和实际代币统计可用资金。

## 6. 资本与库存

```ts
interface ChainInventory {
  chainId: number
  tokenAddress: string
  availableAmount: bigint
  reservedAmount: bigint
  pendingBridgeAmount: bigint
  pendingTxAmount: bigint
}
```

只有交易最终确认、代币地址正确且未被其他订单预占的资产，才能计入“可用余额” `availableAmount`。至少设置以下限额：

- 每条链、每种资产和每笔交易可占策略总资产价值（NAV）的上限；
- 每座桥的在途资金上限、每个地址的代币授权额度上限；
- 每日网络手续费和失败损失上限；
- 停机后的最低应急余额。

## 7. 回测最低要求

### 数据

保存时间、区块、链、代币地址、输入量、预计到账量 `toAmount`、最低可接受到账量 `toAmountMin`、网络手续费、其他费用、使用工具、交易路径、响应时间和原始响应。

### 执行仿真

至少模拟：报价到发送的延迟、两笔交易确认的时间差、买卖只有一笔成功、网络手续费和补库存成本/耗时的中位数与 95 分位、`PARTIAL/REFUNDED/FAILED`、库存不足，以及节点接口/API 限流。

### 报告

- 总盈亏、相对基准多赚或少赚多少、扣费前/扣费后/按最低到账计算的价差；
- 最大回撤、买卖只有一笔成功的发生率与损失分布、价差缩小一半需要多久；
- 不同交易金额下的可盈利范围、资金实际使用比例、跨链在途资金占比；
- 补库存成本占毛利比例，以及各链/工具失败率。

## 8. 从研究进入小额真实交易前的检查

- [ ] 按链 ID + 代币地址匹配资产，并正确处理代币小数位（decimals）。
- [ ] 已实现获取最新报价、判断报价过期和重新模拟。
- [ ] 已实现买卖只有一笔成功时，自动补做失败的交易或临时进行反向保护。
- [ ] 已分别实现“只完成一部分、已退款、失败”的处理流程。
- [ ] 已设置链、桥、代币、单笔交易和每日损失限额。
- [ ] 回测使用 95 分位成本（较差的 5% 情况），并覆盖库存不足和基础设施异常。
- [ ] 已完成至少一个完整波动周期的模拟交易。
- [ ] 已用小额真实交易校准报价与实际成交偏差。
- [ ] 已定义日亏损、连续失败和基础设施异常的停机条件。
