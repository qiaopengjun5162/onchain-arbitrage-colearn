# 模型三：同链 DEX 间套利

## 一句话结论

在同一条链的不同交易场所完成 `起始资产 → 中间资产 → 起始资产`。能否真实自动交易，关键不是看到两个不同报价，而是用自己的合约在一笔交易中完成整个循环，并在链上检查最低利润。

## 1. 模型与 LI.FI 的作用

```text
USDC -> WETH（便宜场所）
WETH -> USDC（贵场所）
最终 USDC > 初始 USDC + 全部成本
```

LI.FI 可提供同链兑换报价（Swap Quote），通过 `allowExchanges` 指定使用哪些交易所，并返回最低到账量 `toAmountMin`、网络手续费、授权合约地址和合约调用数据；也可用不同交易金额测试价格影响。

边界：1inch、0x、Odos 等报价聚合服务可能访问同一个底层资金池；两个服务给出的报价不同，不代表两边能同时成交并赚钱。分开发送两份普通 `transactionRequest`，可能只成功一笔。LI.FI Contract Calls 仍处于测试阶段（Beta），不能未经安全审查就直接承担高频自动交易。

## 2. 推荐前提

| 维度 | 必须具备 |
|---|---|
| 全部成功或全部失败 | 经过测试和安全审查的合约在一笔交易中执行两步，并用最终余额验证最低利润 `minProfit`；否则只适合研究 |
| 安全 | 代币、交易路由合约（Router）、被授权转账的地址（spender）和允许调用的函数全部使用白名单；不接受任意合约调用数据；长期资产与交易资金隔离 |
| 模拟与提交 | 按准备成交的区块状态模拟完整流程；模拟节点与发送节点保持同步；有私有交易通道和可信打包方，或已量化公开等待打包时的损失 |
| 路径与资产 | 识别真正使用的资金池，排除两边重复使用同一池；代币不能有未知转账税、余额自动变化、转账时回调其他合约或黑名单等特殊行为 |
| 经济性 | 完整循环在目标金额下仍盈利；机会持续时间足够完成报价、模拟和上链；能够承担交易失败后仍支付的网络手续费，并设置每日上限 |
| 资金 | 使用自有本金或已验证的闪电贷（同一笔交易内借入并归还）；执行地址有充足网络手续费；代币授权额度尽量小，或使用受控的 Permit2 签名授权方式 |

## 3. 两种执行方式

| 方式 | 流程 | 权衡 |
|---|---|---|
| 自有本金 | 合约用 USDC 买 WETH、再卖回 USDC，最后检查余额 | 占用本金较多，路径较简单 |
| 闪电贷（Flash loan） | 借 USDC、完成循环、在同一笔交易中归还本息，剩余为利润 | 减少自有本金，但增加借款费、网络手续费、回调和重复进入合约的攻击风险 |

## 4. 机会与执行流程

1. 对同一输入量，分别指定不同交易所来源获取报价。
2. 解析 `includedSteps`，查看报价真正使用了哪些资金池、是否拆成多条路径，以及两边是否重复使用同一资金池。
3. 构造 `A → B → A` 完整循环。
4. 用第一笔交易的最低或模拟到账量作为第二笔输入，并按顺序更新资金池状态。
5. 扣除两笔交易的网络手续费、协议费、闪电贷费用、给交易打包方的额外费用和失败准备金。
6. 在同一区块状态模拟完整原子调用。
7. 只有链上最低利润条件 `minProfit` 通过时才提交。

不能直接组合两个独立报价的展示结果：第二笔的输入数量取决于第一笔真实拿到多少，而且第一笔本身会改变资金池价格。

## 5. 盈亏

```text
netProfit
= finalBaseToken - initialBaseToken
- gasCost
- flashLoanFee
- builderTip
- protocolFees

链上断言：endingBalance >= startingBalance + minProfit
```

直白地说：最终拿回的 USDC 减去最初投入的 USDC，再减去网络手续费、闪电贷费用、打包方额外费用和协议费，才是真实利润。合约还必须在链上确认利润至少达到 `minProfit`。

最低利润条件不满足时，整笔交易会失败并回滚，但网络手续费仍会损失。

## 6. 损失与控制

| 风险 | 如何亏损 | 关键控制 |
|---|---|---|
| 两笔交易不能一起回滚 | 第一笔成功后，第二笔失败或价差消失，账户留下本来不想持有的中间资产 | 真实自动交易只使用“全部成功或全部失败”的单笔合约；否则只做模拟交易 |
| 两条报价路径重叠 | 两个报价服务实际使用同一资金池，第一笔交易完成后，第二笔的好价格就消失了 | 查看真正使用的资金池，不能只看报价服务的名称 |
| 自身价格影响 | 第一笔改变资金池储备和当前价格区间，旧的第二笔报价会高估到账 | 按执行顺序模拟，或复制历史区块状态后运行完整交易 |
| 抢跑和插队 | 交易被复制、抢先或夹击，或者打包方不收录；额外费用过高也会让成功交易反而亏损 | 使用私有通道；分别回测公开/私有提交；限制给打包方的额外费用 |
| 失败手续费 | 整体回滚能保护本金，但竞争激烈时大量失败交易仍消耗网络手续费 | 限制单笔和每日失败手续费，超过预设上限就暂停 |
| 状态过期 | 从获取报价、生成调用数据、模拟到打包期间，资金池状态改变 | 限制报价有效时间；提交前模拟；用链上 `minProfit` 最低利润检查兜底 |
| 有特殊规则的代币 | 转账税、卖出税、余额自动变化、转账回调或黑名单会让预计数量失真 | 只使用检查过的代币，并按交易前后的真实余额差结算 |
| 交易合约/调用数据 | 允许任意目标或调用可能转走合约余额；交易合约或授权地址变化也会造成错误 | 对目标、被授权地址和函数做白名单；最小授权；合约升级后重新检查 |
| 闪电贷 | 费用变化、可借资金不足、回调攻击、还款不足或网络手续费过高 | 验证来源和费率；防止合约被重复进入；在复制的链上状态中完整测试 |
| 基础设施 | 节点返回旧数据、节点不同步、交易序号或私有通道故障 | 使用同步的数据源、确保重试不会重复发交易，并准备备用节点/通道 |

## 7. 回测

LI.FI 不提供完整的历史报价库，需要持续保存报价快照，或重建历史区块中的资金池状态。严格回放应：

1. 读取历史区块的真实池状态；
2. 执行第一笔交易并更新状态；
3. 用真实到账量执行第二笔交易；
4. 计入当时的基础网络费、加速费、闪电贷费和打包方额外费用；
5. 模拟竞争者先成交与失败概率；
6. 记录成功率和失败交易消耗的网络手续费。

报告成功交易利润、失败网络手续费、价差缩小一半所需时间、考虑竞争后的成交率、不同金额下的可盈利范围、打包方额外费用占比，以及每个底层资金池贡献的收益。

## 8. 是否适合开始

### 可以开始（Go）

- [ ] 原子执行合约经过测试与审计。
- [ ] 在复制的历史区块状态中，完整循环而非两个独立报价能够盈利。
- [ ] 扣除失败交易手续费和打包方额外费用后，平均仍能赚钱。
- [ ] 已排除底层路线重叠假象。
- [ ] 私有提交通道可用，故障时有不会扩大损失的备用方案。
- [ ] 代币、交易路由合约、被授权地址和调用数据白名单完整。

### 不应开始（No-Go）

- 计划用两笔钱包交易顺序执行高频套利；
- 没有链上最低利润检查；
- 只比较聚合器名称；
- 无法承担大量失败交易的网络手续费；
- 使用不熟悉的小众代币或允许任意合约调用数据。
