# 基于 LI.FI 的六种套利模型

> 更新日期：2026-08-07
> 本目录用于策略研究、回测设计和风险评审，不构成收益承诺或个性化投资建议。

## 文档范围

LI.FI 是获取报价、选择交易路径和生成交易的基础设施，不是历史行情库，也不能保证一笔跨链操作的所有步骤全部成功或全部失败。本目录研究如何利用 LI.FI 的同链报价、跨链路径、意图订单（Intents）、Earn、Composer 和状态跟踪能力构造六种策略模型。

## 初学者术语表

| 术语 | 直白解释 |
|---|---|
| Token（代币） | 链上的一种资产。判断是否为同一资产时，要同时看链和合约地址，不能只看名称 |
| DEX（去中心化交易所） | 在链上用智能合约完成兑换的交易场所 |
| Quote（报价） | 按指定金额询问“现在交易，预计能拿到多少”。报价不等于最终一定成交 |
| Route（交易路径） | 一笔兑换或跨链经过哪些交易所、资金池和桥 |
| Gas | 支付给区块链网络的手续费。交易失败也可能照样支付 |
| 滑点 | 报价到实际成交之间的价格变差，或大额交易自己推高/压低价格造成的损失 |
| 流动性 / 交易深度 | 某个价格附近有多少资金愿意和你交易。越深，交易大额资产时价格越不容易变差 |
| 原子执行 | 多个步骤要么全部成功，要么全部失败回滚；不会只完成一半 |
| 买卖只成功一笔 | 套利通常需要同时买入和卖出。如果买入成功但卖出失败，或卖出成功但买入失败，就会意外持有过多或过少资产 |
| 在途资金 | 交易或跨链已经发出，但尚未最终到账、暂时不能再次使用的资金 |
| MEV | 其他人通过抢先、插队或夹在交易前后成交，从你的交易中获取价值 |
| RPC | 程序连接区块链节点的接口；故障或数据落后会影响报价、模拟和发交易 |
| allowance（授权额度） | 允许某个合约从钱包最多转走多少代币 |
| NAV（总资产价值） | 策略当前持有的全部资产按统一货币折算后的价值 |
| PnL（盈亏） | 收益减去所有成本和损失后的结果 |
| Delta（方向敞口） | 资产价格涨跌时，策略净值会跟着变化多少 |
| 对冲 | 做一笔方向相反的交易，减少资产涨跌对整体资金的影响 |
| 清算 / 强制平仓 | 抵押物或保证金不够时，协议强制卖掉仓位偿还债务 |
| 毛利 / 净利 | 毛利是扣费前赚到的价差；净利是扣除手续费、滑点、失败和资金成本后真正剩下的收益 |
| 脱锚 | 稳定币明显偏离本应保持的价格，例如 1 USDC 不再接近 1 美元 |
| 赎回 | 把稳定币或金库凭证按规则换回其底层资产 |
| 白名单 | 只允许程序使用事先检查过的代币、合约、桥和交易所 |
| 回测 | 用历史数据模拟策略过去会如何交易和盈亏 |
| 压力测试 | 假设价格暴跌、手续费暴涨、交易失败等极端情况，检查最多可能亏多少 |
| 最大回撤 | 策略资金从某个历史高点跌到之后最低点的最大跌幅 |
| P95 / P99 | 95% / 99% 情况下不会超过的成本或耗时，用来观察较差而非平均情况 |
| APY（预计年化收益率） | 按当前收益水平推算一年的收益率，不代表未来锁定收益 |
| TVL（锁仓总价值） | 某协议或金库当前存入的资产总价值 |
| paper trading（模拟交易） | 使用真实行情做决策，但不真正动用资金 |
| revert（失败回滚） | 链上交易没有完成状态修改，但网络手续费通常不会退 |

## 六种模型对比

| 模型 | 收益来源 | 是否要求预置库存 | 能否全部成功或全部失败 | 主要损失来源 | 推荐度 |
|---|---|---:|---|---|---:|
| 多链预置库存 | 不同链现货价差 | 是 | 每条链内可以；跨链整体不可以 | 资产涨跌、买卖只成功一笔、补库存 | 高 |
| 稳定币跨链价差 | 稳定币在不同链或不同版本之间的价格差 | 是 | 跨链步骤可能只完成一部分 | 脱锚、桥包装资产、流动性枯竭 | 中高 |
| 同链 DEX 间套利 | 同链不同交易场所的价差 | 可选 | 需自有合约做到“全部成功或全部失败” | 被抢跑、网络手续费、买卖只成功一笔、路径重叠 | 中 |
| 接单成交方 vs DEX | 接单方库存报价与自动做市资金池的报价差 | 视执行方式 | 取决于订单与反向交易结构 | 报价失效、订单未成交、反向交易失败 | 中 |
| 跨链循环 | 跨链一圈后，回到原资产时多出来的数量 | 否或部分 | 可能只完成一部分 | 桥接延迟、价差消失、只完成一部分 | 低 |
| Earn 金库轮动 | 预计年化收益率之差减去迁移成本 | 是 | 同链阶段可整体回滚，跨链不能 | 收益率下降、本金损失、退出受限 | 中 |

## 先给结论

- 第一优先：多链预置库存套利。它把桥接移出对时延敏感的关键路径，最接近可持续执行模型。
- 第二优先：高质量稳定币跨链价差。方向波动较低，但必须把脱锚和桥接版本视为信用风险。
- 第三优先：同链 DEX 和“接单方 vs DEX”。适合做报价研究，真实自动交易需要能让多步操作整体回滚、及时做反向交易，并降低被抢跑的损失。
- 研究用途：跨链循环。可以发现结构性价差，但不能把当前两段报价当作可锁定利润。
- 配置用途：Earn 轮动。它更接近“持有一段时间赚取收益差”，而不是瞬时无风险套利。

## 所有模型共同的前提

- 使用链 ID + 代币合约地址识别资产，不能只看代币简称。
- 使用 `toAmountMin` 而非 `toAmount` 计算保守收益。
- 将网络手续费（Gas）、协议费、价格影响、失败准备金和资金占用成本全部计入。
- 检查报价是否过期、链上模拟、交易序号（nonce）、节点接口（RPC）、余额和代币授权额度（allowance）。
- 分别处理 `COMPLETED`（完成）、`PARTIAL`（只完成一部分）、`REFUNDED`（已退款）和 `FAILED`（失败），不能只用“成功/失败”两种结果。
- 回测必须模拟“买入和卖出只有一笔成功”、桥接延迟、流动性收缩和网络手续费暴涨。
- 上线顺序应为：历史数据回放 → 模拟交易 → 小额真实交易校准 → 设置限额后自动执行。
