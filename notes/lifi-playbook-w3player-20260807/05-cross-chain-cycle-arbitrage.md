# 模型五：跨链循环套利

## 一句话结论

从链 A 的资产 `X` 出发，经过链 B 后再回到链 A 的 `X`，目标是最后拿回更多 `X`。逻辑直观，但跨链过程中可能只完成一部分，返程价格也无法提前锁定。一步接一步等待到账的版本更适合研究；要进行较大规模的真实交易，通常需要提前在多条链放好库存。

## 1. 模型与 LI.FI 的作用

```text
链 A: X
  -> 兑换/跨链
链 B: Y
  -> 兑换/跨链
链 A: X'
```

只有 `X' - X` 覆盖所有手续费、失败准备金和资金占用成本后，才是真正的利润。

LI.FI 可以提供：

- 双向报价和交易路径；
- 多个桥与 DEX 候选；
- 可直接发送的交易请求 `transactionRequest`；
- 预计到账量 `toAmount` 和最低到账量 `toAmountMin`；
- 网络手续费、其他费用，以及“完成、部分完成、已退款、失败”等状态。

它不能保证整个循环要么全部成功、要么全部失败：第一段完成时，第二段面对的价格和流动性已经可能变化。

与[多链预置库存](./01-prefunded-cross-chain-inventory.md)相比，本模型把桥接放进交易闭环，因此更依赖路径、时间和返程报价；预置库存模型则把桥接推迟到事后，代价是长期库存占用。

## 2. 两种实施方式

| 方式 | 做法 | 优点 | 代价 |
|---|---|---|---|
| 逐步等待到账 | 等 A→B 实际到账，再以真实数量执行 B→A | 记录和对账简单，无需长期在目标链放库存 | 返程无法锁价；价差可能消失；桥接和退款占用资金；中途失败会留下 Y |
| 预置库存加速 | 链 B 用预置 Y 立即执行返程，A→B 到账后补回库存 | 两段更接近同时成交，减少桥延迟带来的价格风险 | 引入多链库存、库存缺口、补库存和每条链的金额上限 |

逐步等待到账更适合研究报价是否合理；要稳定进行真实交易，通常只能采用第二种，并使用模型一的库存风险控制。

## 3. 推荐前提

| 维度 | 必须具备 |
|---|---|
| 市场 | 价差具有持续性；正反路径存在独立定价/流动性；目标金额扣除价格影响后仍盈利；至少有两条替代桥/退出路径 |
| 资产 | 按链和合约地址区分原生资产、包装资产和桥接凭证；中间资产必须能够可靠估价、卖出和恢复 |
| 资金 | 可承受桥接和退款期间的资金占用；设置每条链的库存和损失预算；目标链有支付网络手续费的原生代币；预置版本能承受两笔相关交易中只有一笔成功，以及连续同方向交易；计入真实资金时间成本 |
| 系统 | 报价、签名、发送交易和状态跟踪自动化；只有真实到账后才触发下一段；处理“部分完成、已退款、超时”；支持链重组、节点接口、交易序号和网络手续费异常 |
| 安全 | 代币、桥、DEX、交易路由合约和中间资产都使用白名单；保存报价、成交、耗时、到账差异和失败原因 |

## 4. 执行流程

1. 确定起始资产 `X`、链 A、链 B 和中间资产 `Y`。
2. 查询 A→B 路径，记录预期/最低到账、成本与耗时。
3. 用第一段的保守到账量查询 B→A。
4. 合并两段网络手续费、协议费、桥费、滑点、失败准备金和资金占用成本。
5. 保守利润超过事先规定的最低标准后，才执行第一段。
6. 核对链 B 的真实资产和到账量，并重新获取返程报价。
7. 新报价仍符合退出条件才执行；否则按预案接受损失退出、继续等待、更换路径或暂时保留链 B 库存。
8. 回到链 A 后，以真实 `X'` 结算完整循环。

预置版本可提前执行返程交易，但跨链补库存仍是未完成事项，必须一直跟踪到最终到账。

## 5. 盈亏

```text
grossPnl = finalX - initialX

netPnl
= grossPnl
- twoLegGas
- bridgeAndProtocolFees
- slippageAndPriceImpact
- hedgeCost
- capitalTimeCost
- failureAndRecoveryCost

conservativeFinalX
= 第二段基于第一段保守到账量计算的 toAmountMin
```

直白地说：完整绕一圈后多出来的 `X`，还要减去两段网络手续费、桥费、交易费、滑点、资金占用以及失败恢复成本，剩下的才是净利。

不能把同一时刻的两个最佳报价直接相乘：第二个报价在第一段到账时通常已过期。

## 6. 损失与控制

| 风险 | 如何亏损 | 关键控制 |
|---|---|---|
| 桥接期间价格反转 | 到达链 B 时返程收益消失；延迟和价格波动会增加小概率大额亏损 | 逐步等待版本必须预留更大利润空间；限制资产波动和最长完成时间 |
| 第二段失效 | 返程路径因流动性、网络手续费、区块或第三方报价变化而不可用 | 到账后强制重新报价；准备替代退出；禁止直接发送早已生成的旧交易 |
| 只完成一部分 | 桥接成功，但目标链兑换失败，因此只收到中间资产 | 按实际收到的代币入账；只接收检查过的资产，并准备专门恢复流程 |
| 退款/长时间占款 | 退款所在链、金额和时间可能变化，期间资金也不能用于其他机会 | 一直标记为在途资金；按较慢 5%/1% 情况准备资金和超时处置 |
| 多段费用叠加 | 每段都增加桥费、DEX 费、网络手续费与滑点；小额被固定费用吞噬，大额又会明显推高价格 | 测试不同交易金额；按 `toAmountMin` 和较差 5% 成本决定是否交易 |
| 中间资产 | 包装资产、桥接凭证或小众稳定币可能脱锚、冻结或难以赎回 | 按合约地址设置白名单并降低估值；限制最多持有多少中间资产 |
| 前一步影响后一步 | 第一笔交易改变目标资金池；其他套利者也可能先用掉返程的交易深度 | 按真实顺序模拟；优先使用独立资金池；预置库存减少等待 |
| 抢跑和插队 | 同链兑换被抢先、夹击或复制，原本很薄的利润被别人拿走 | 私有提交、严格限制滑点并设置最低利润 |
| 链/桥/协议 | 链暂停、交易确认异常、节点接口、桥验证程序或合约故障；多套系统风险叠加 | 分别限制链、桥和协议金额；准备替代路径并自动暂停 |
| 目标链无手续费余额 | 资产已到账，但钱包没有该链原生代币来支付返程交易 | 预先存放并监控各链手续费余额，保留应急补充 |
| 年化收益被高估 | 忽略桥接和退款时间，只按成交次数计算，会夸大资金一年能重复使用多少次 | 按资金实际被占用的时间计算年化收益 |
| 回测偷看未来 | 用同一时刻的两段报价，等于假设提前知道返程价格；用今天的路径回放历史也会失真 | 按真实或采样延迟推进时间，并保留历史路径与失败样本 |

连续失败、桥接时间异常或价差消失得越来越快时自动暂停。预置版本还需设置库存偏离上限，并隔一段时间统一计算净缺口后再补库存。

## 7. 回测

LI.FI 提供当前报价与执行，不是完整历史报价库；需要自行采集：

- 请求/响应时间，以及路径、工具、代币、链和交易金额；
- 预计到账量 `toAmount`、最低到账量 `toAmountMin`、网络手续费、其他费用和报价有效期；
- 广播、源链确认、目标链到账时间；
- 实际到账地址/数量、状态与失败原因；
- 到账时重新查询的返程报价和最终 `X'`。

正确回放必须推进时间：

```text
t0：第一段报价与成交
t1 = t0 + 模拟桥耗时：使用当时的第二段报价
t2：计入第二段成交/失败和最终确认
```

报告：

- 报价显示的扣费前利润与实际扣费后利润之差，以及价差缩小一半需要多久；
- 桥接耗时的中位数、95 分位、99 分位，返程仍盈利的概率和各状态比例；
- 最大亏损、资金占用与真实年化，以及不同交易金额下的可盈利范围；
- 桥、链和中间资产的风险贡献。

压力测试覆盖价格突然大幅变化、网络手续费激增、延迟扩大、目标链暂停、交易深度减半和中间资产脱锚。

## 8. 是否适合开始

### 可以开始（Go）

- [ ] 压力场景的最低到账仍覆盖全成本。
- [ ] 价差持续时间明显长于从第一步开始到最后一步确认的总时间。
- [ ] 有第二退出路径和中间资产处置方案。
- [ ] 能承受较慢 5%/1% 桥接情况下的资金占用。
- [ ] 状态跟踪、恢复和对账已自动化。
- [ ] 单次失败不突破链级或组合预算。

### 不应开始（No-Go）

- 利润依赖两个同时看到但无法锁定的报价；
- 只有乐观 `toAmount` 下盈利；
- 返程无替代流动性，中间资产无法估值/退出；
- 目标链没有支付网络手续费的原生代币，或没有异常恢复流程；
- 一次“只完成一部分”或退款造成的损失，就能吞掉长期利润；
- 回测未模拟桥接延迟和机会衰减。
