# 模型一：多链预置库存套利

## 一句话结论

在便宜链买入、贵链卖出等量资产，桥接只负责事后补库存。它把桥接移出价格敏感路径，是六种模型中最值得优先研究的；代价是长期占用多链库存，并承担“买入和卖出只有一笔成功”以及库存偏移的风险。

## 1. 模型与 LI.FI 的作用

```text
便宜链：USDC -> 买入 Q WETH
贵链：  卖出 Q WETH -> USDC
```

买入和卖出都成功后，全局 WETH 近似不变，WETH 与 USDC 只是在链间迁移；全局 USDC 增量是扣费前收益。优先等待反向机会自然恢复库存，超过库存上下限时再跨链。

LI.FI 可以：

- 获取各链的可执行报价（Quote）；
- 指定使用哪些交易所；
- 返回最低到账量 `toAmountMin`、网络手续费和其他费用；
- 返回授权合约地址和交易调用数据；
- 生成补库存的跨链路径，并通过 `/status` 核对实际到账。

LI.FI 不能让不同链的两笔交易做到“全部成功或全部失败”，也不会替策略承担其中一笔失败后的价格风险。

## 2. 推荐前提

| 维度 | 必须具备 |
|---|---|
| 市场 | 两链都有持续流动性；价差持续时间足够完成报价、模拟、签名和上链；不同交易金额下仍有净利；代币无异常税费或转账限制；按较差 5% 情况估算的补库存成本仍可接受 |
| 资金 | 各链有买入资产、卖出资产和支付网络手续费的原生代币；有补做失败交易用的应急稳定币；在途资产不算可用；收益率按闲置与在途资金计算 |
| 系统 | 监控节点接口（RPC）、余额、交易序号（nonce）、网络手续费和代币授权额度；超时后重新报价和模拟；按目标资产数量匹配并正确处理小数位；两笔交易尽量同时发送；具备补做失败交易、减仓、反向保护和跨链恢复能力 |
| 防抢跑 | 通过私有通道提交交易，或已量化公开等待打包时被夹击、抢跑和交易失败造成的损失 |

研究起始值可设为：

```text
单链资产价值：策略总资产价值的 25%–35%
单笔用量：该链对应资产可用库存的 5%–10%
买卖未平衡金额：策略总资产价值的 1%–2%
网络手续费储备：至少 20 笔交易
应急稳定币：至少 2 个最大批次
```

这些只是待回测参数，不是通用安全线。

## 3. 库存融资方式

| 方式 | 适用前提 | 新增风险 | 推荐 |
|---|---|---|---|
| 长期持币增强 | 本来就长期持有 ETH/WETH | 承担完整价格回撤；需与“相同金额一直持有不动”比较多赚了多少 | 首选 |
| 永续合约对冲 | 有低杠杆保证金、资金费率（Funding）、强制平仓监控和备用交易场所 | 资金费率、现货与合约价格差、平台故障、强制平仓和数量错配 | 次选 |
| 借入 WETH | 有足够多的抵押物、较安全的借款健康度（Health Factor）、应急还款与利率监控 | 利率跳升、抵押品下跌、强制平仓、跨链后无法及时还款 | 最复杂，不建议首版 |

永续合约版本的风险资产净敞口（Delta）：

```text
netDeltaEth = totalSpotEth - shortPerpEth
```

因此，“适合长期持有时才做”只适用于未对冲版本；对冲和借币版本不要求长期看多，但会引入更复杂、可能更致命的风险。

## 4. 执行流程

1. 获取各链相同交易金额的双向可执行报价，计算真实买卖价。
2. 发现候选后重新询价，并让买入和卖出的 WETH 数量一致。
3. 按最低到账量 `toAmountMin`，扣除两边网络手续费、其他费用、预期补库存成本和失败准备金。
4. 检查库存、交易序号、节点接口、代币授权额度和报价是否过期。
5. 尽量同时提交买卖；设置各自的最低到账量和最晚成交时间（deadline）。
6. 读取链上交易结果（receipt）与真实余额，核对两边成交数量。
7. 更新可用、已预留和处理中三类库存（`available/reserved/pending`）。
8. 先等待反向成交；库存达到提醒线或强制处理线后，再计算总缺口并统一补库存。

## 5. 盈亏

```text
netArbitragePnlUsd
= sellProceedsUsd - buyCostUsd
- buyGasUsd - sellGasUsd - tradingFeesUsd
- expectedRebalanceCostUsd
- hedgeOrBorrowCostUsd
- expectedFailureLossUsd

totalPnl
= netArbitragePnl
+ inventoryMarkToMarket
+ hedgePnl
- fundingOrBorrowInterest
- liquidationLoss
- operationalLoss
```

直白地说：先计算一买一卖真正赚到的价差，再减去手续费、补库存、对冲或借款、交易失败等成本；最后还要把库存本身的涨跌算进整个策略的盈亏。

## 6. 损失与控制

| 风险 | 如何亏损 | 关键控制 |
|---|---|---|
| 资产方向 | 没有反向保护时 WETH 下跌；价格上涨时若卖出成功、买入失败，也会落后于一直持有 | 分开报告库存涨跌和相对单纯持有的结果；限制风险资产净敞口 |
| 买卖只成功一笔 | 意外持有过多或过少 WETH；补做失败的交易时遭遇价格反转、滑点、抢跑和额外网络手续费 | 限制两笔交易的发送时间差、未匹配金额和持续时间；准备自动补做和备用反向交易 |
| 数量不匹配 | 相同美元金额不等于相同 WETH；费用、价格冲击和小数位错误留下方向风险 | 按目标资产数量匹配；成交后按真实余额校准 |
| 报价过期 | 资金池变化、交易排队或第三方响应慢；限制过严导致交易失败，限制过宽会被抢跑 | 限制报价有效时间；重新报价和模拟；使用 `toAmountMin` 与私有提交 |
| 补库存 | 桥费和双链网络手续费；资金在途闲置；目标链兑换失败；只完成一部分时收到中间代币；长期单向价差迫使高价补库 | 优先等待反向机会；限制在途资金；按实际代币入账；准备替代桥和恢复路径 |
| 流动性/可交易金额 | 小额交易能赚钱，不代表放大金额后仍能赚钱；紧急补做交易时深度通常更差 | 测试不同交易金额，并用市场危机时的交易深度做压力测试 |
| 链/协议/基础设施 | 链上交易排序器、节点接口、桥、DEX 交易合约或 LI.FI 合约异常 | 分散链、代币、桥、DEX 和节点接口并分别限额；异常时自动停机 |
| 对冲/借款 | 资金费率、现货与合约价格差、平台故障、强制平仓；借款利率、抵押品、健康度与还款失败 | 低杠杆、单独设置风险规则、准备备用交易场所和应急还款资金 |
| 操作与系统 | 错地址、小数位、chain ID、无限授权、交易序号、重复发送、私钥泄露 | 严格白名单、最小授权、只执行一次的重试设计、密钥隔离与对账 |

买卖数量不匹配造成的损失沿用[公共模型](./00-common-model.md)：

```text
mismatchLoss
= unmatchedWeth * adversePriceMove
+ emergencySlippage
+ emergencyGas
```

连续失败、网络手续费异常、节点返回互相矛盾的数据、余额不一致或桥暂停时应自动停机；先控制总体价格风险，再恢复各链库存。

## 7. 回测

至少采集每条链的双向报价、最低到账量 `toAmountMin`、网络手续费、其他费用、响应时间、区块号、真实资金池状态、不同金额的可交易容量、两笔交易确认时间/失败率、桥接耗时/状态/到账代币，以及永续合约资金费率或借款年利率。

必须报告：扣费后价差、价差缩小一半所需时间、资金实际使用比例、相对单纯持有多赚或少赚多少、最大风险资产净敞口、买卖只有一笔成功时的损失、补库存成本占毛利比例和最大资金回撤。

## 8. 是否适合开始

### 可以开始（Go）

- [ ] 按较差 5% 的完整成本估算后，仍有稳定利润空间。
- [ ] 压力测试中，买卖只有一笔成功造成的损失不超过预算。
- [ ] 补库存成本不会长期吞掉大部分扣费前收益。
- [ ] 任一链停机不危及全部资金。
- [ ] 资产涨跌、资金费率、借款与强制平仓风险已分别计算。
- [ ] 模拟交易与小额真实交易的偏差在模型允许范围内。

### 不应开始（No-Go）

- 无法承担多链闲置库存，或无法自动处理“买卖只有一笔成功”；
- 只看页面展示价格，不获取可执行报价；
- 需要等待桥接后才能完成卖出；
- 只有使用高杠杆时收益才有吸引力。
