# 模型四：接单成交方（Solver）与 DEX 报价差套利

## 一句话结论

比较两种成交方式的报价：一种由接单成交方（Solver）负责完成，另一种走普通 DEX 或跨链桥。只选择更划算的一边，叫“选择最佳成交方式”，不是套利。只有一边价格已经锁定，另一边又能几乎同时做一笔方向相反的交易，价差才可能真正变成利润。

## 1. 模型与三种形态

```text
普通路由：li.quest /v1/quote
意图订单（Intent）：order.li.fi /quote/request
```

意图订单只说明用户“想付出什么、最终得到什么”，不规定中间怎么走。Solver 是接下订单并负责把结果交付出来的一方；它可以使用自有库存、中心化交易所（CEX）、去中心化交易所（DEX）或非公开流动性，因此报价可能优于或劣于普通自动做市资金池。

| 形态 | 做法 | 本质 |
|---|---|---|
| 选择最佳成交方式 | 比较 Solver 与普通路径，选择扣费后到账更多的一边 | 只是少付成本，不是独立套利 |
| 锁定报价 + 反向交易 | 锁定 Solver 报价，同时在 DEX/CEX 做方向相反的交易 | `报价差 - 反向交易与结算成本` |
| 自己成为 Solver | 长期发布可接单报价，收到订单后先交付，再取回用户锁定的资产 | 类似专业做市；需要注册、多链库存、订单系统、结算和信誉管理 |

## 2. 推荐前提

| 维度 | 必须具备 |
|---|---|
| 报价可比 | 付出/收到的资产、链、数量、收款地址（receiver）、最晚成交时间（deadline）一致；同时确认是“固定付出数量”还是“固定收到数量”；统一扣除网络手续费、服务费、Solver 费用、桥费、反向交易费和资金占用 |
| 报价状态 | 能区分指示性、可提交、已签名和已锁定；比较最低输出与订单约束，不只看展示价格 |
| 反向交易 | 有足够交易深度的反向场所；可以在订单产生价格风险之前或几乎同时成交；能处理未成交、只完成一部分、过期和退款，并快速卖掉或买回多余资产 |
| 订单全过程 | 同时获取普通报价、意图订单报价和订单状态；跟踪“已签名 → 已交付 → 已结算”；区分最晚交付时间 `fillDeadline` 和最终退款时间 `expires` |
| 结算 | 核验目标链是否交付、验证程序是否认可、资金是否释放；分别限制每个 Solver、链、资产和路径的金额 |
| 自己做 Solver | 有多链目标资产库存、快速交付、长期报价、实时接单和信誉管理能力 |

## 3. 执行流程

### 普通接入方 / 反向交易模式

1. 用完全相同的资产、链和数量，同时获取普通报价和意图订单报价。
2. 统一金额、费用、网络手续费、有效时间和成功条件。
3. 若只是替用户成交，选择扣费后到账更多的一边。
4. 若要套利，先确认一边价格已经锁定，再执行方向相反的交易。
5. 同时跟踪订单和反向持有的资产，直至交付、结算或退款。

### 自己作为 Solver

1. 按金额区间长期发布可接单报价。
2. 接收匹配订单，复核最新反向交易价格和库存。
3. 在目标链交付资产，等待验证程序确认。
4. 从负责源链结算的合约中取回锁定资金。
5. 更新库存、盈亏、延迟和信誉指标。

## 4. 盈亏

```text
netPnl
= lockedSolverPriceEdge
- hedgeSlippage - hedgeFees
- sourceAndDestinationGas
- settlementCost
- inventoryFundingCost
- timeoutOrUnwindLoss
- failureReserve
```

直白地说：净利 = 已锁定的 Solver 报价优势 − 反向交易的滑点和手续费 − 两条链的网络手续费 − 结算与资金占用成本 − 超时平仓和失败准备金。

未锁定的报价只能记录为“看到过的价差”，不能算作可以拿到的利润。

## 5. 损失与控制

| 风险 | 如何亏损 | 关键控制 |
|---|---|---|
| 把参考报价当成锁定报价 | Solver 价格在提交或签名前变化；提前做的反向交易变成只剩一个方向、没有保护的持仓 | 明确标记“仅观察、可提交、已签名、已锁定”等状态 |
| 未按时交付 | `fillDeadline` 前未成交，可能到更晚的 `expires` 才能退款；资金和反向持有的资产一直被占用 | 设置最大等待时间；计入持有反向资产期间的费用、价格波动和资金占用成本 |
| 反向交易成交、订单失败 | Solver 没接单、拒绝或过期；卖掉或买回反向资产时遭遇价格反转、费用和滑点 | 限制反向交易可以提前多久；预设撤销或反向成交路径 |
| 订单成交、反向交易失败 | 交付已经发生，但外部市场没深度、接口失败或价格跳变，留下单边价格风险 | 准备多个交易场所；优先降低资产涨跌风险；设置持有金额硬上限 |
| 对手只挑有利时成交 | 对手在对你不利、对它有利时才成交；长期报价等于免费给出选择权 | 长期报价必须覆盖最差延迟、价格波动和反向交易成本 |
| 名称相同但资产并不等价 | 所在链、代币版本、中心化交易所参考价、赎回或桥接权利不同 | 用合约地址和真实可兑换权利判断是否真的是同一种资产 |
| 交付验证和结算 | 已交付但证明或数据同步延迟；验证/结算合约异常；编码错误导致交付不被认可 | 本地校验订单 ID、链、地址和签名；一直跟踪到资金释放 |
| 过度依赖单一 Solver | 某个 Solver 的报价质量、成交率或可用性恶化 | 分 Solver 统计，并设置可靠性、金额和路径上限 |
| 库存/资金 | 多链预置资产，源链资金在结算前被锁定；只按成交金额计算收益率，会夸大资金效率 | 按全部占用资金和真实占用时间计算收益率 |
| 签名/API | 交易序号、最晚成交时间、跨链地址格式、签名规则或重试错误 | 本地严格校验；保证重试不会重复下单；防止旧签名被再次使用 |

## 6. 回测

同步保存普通报价、意图订单报价及其有效期/类型、订单状态时间线、反向交易场所的买卖深度与真实成交价、资金费率/手续费/延迟，以及未成交、退款、交付和结算结果。

不能假设看到的 Solver 报价必然成交；回测时应根据真实订单成交率、延迟和反向交易失败率，随机模拟可能结果。

报告：有多少价差真的能锁定、订单成交率、订单和反向交易不匹配造成的损失、平均/95 分位/99 分位交付与结算时间、等待退款占用的资金、各 Solver 的盈亏，以及相比普通路径多到账多少。

## 7. 是否适合开始

### 可以开始（Go）

- [ ] 能区分“选择更优成交方式”和“能够锁定利润的套利”。
- [ ] 反向交易和订单从签名到结算的全过程都可实时核验。
- [ ] 已计入订单未成交后，卖掉或买回反向资产的损失。
- [ ] 按较慢 5% 的交付和结算时间估算后，平均仍能赚钱。
- [ ] 单一 Solver 或反向交易平台故障不危及全部资本。
- [ ] 签名、最晚成交时间、地址和重试逻辑经过测试。

### 不应开始（No-Go）

- 直接相减两个同时看到的报价作为利润；
- 无法判断 Solver 报价是否已经锁定；
- 没有方向相反的保护交易，也没有订单失败处置；
- 无法承受退款或结算期间的资金占用；
- 依赖单一 Solver 或单一反向交易平台。
