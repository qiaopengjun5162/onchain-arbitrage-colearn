# LP 动态调区间：上涨行情也能继续吃 fee

日期：2026-08-05

## 群里的观点

> 涨的时候也可以策略吃，就是得根据情况让程序移动区间。

## 背景机制

集中流动性 LP（Uniswap V3 / Orca Whirlpool / Meteora DLMM）的固有约束：

- 价格跑出设定的区间后，仓位停止赚 fee，且完全变成单一资产。
- 上涨行情中，区间 LP 本质上在持续卖出上涨的资产——价格穿越区间的过程就是边涨边卖的过程。
- 所以"死守一个区间"在单边行情里既踏空又停收 fee。

动态调区间就是把被动 LP 变成主动策略：价格涨了，程序把区间整体上移，让仓位重新回到 fee 收入区。

## 这个策略真正的研究点

调区间不是免费的，每次调整都是一笔真实交易：

- 每次 rebalance 会把浮动无常损失变成已实现损益
- 每次都要付 gas + 滑点 + 可能的 swap 手续费
- 调得太频繁，fee 收入被调整成本吃掉；调得太慢，长时间跑出区间颗粒无收

核心研究问题：

1. 触发条件：价格偏离区间中心多少才调？按固定带宽、ATR、还是波动率自适应？
2. 新区间怎么定：等宽平移、还是根据趋势/波动重新估？
3. 回本账：单次调整成本 vs 预期 fee 收入，多久回本？
4. 回测对比：动态调区间 vs 死守宽区间 vs 直接持有，三条曲线谁好？

## 和监控 Bot 的连接

这就是监控脚本的第一个"策略化"用途：区间状态（价格位置、距边界距离、fee 累积速度）本身就是监控字段，超阈值告警就是调仓触发器的 Paper Trading 版本。先只记录"如果当时调了会怎样"，跑一段时间再谈自动执行。

## 动态套保 = 反向网格：保险本身是亏钱的（2026-08-05）

推演结论：

> 可以动态套保，但这相当于另一个反向网格，而且挂单和吃单手续费不一样，大概率套保的网格还是亏钱的。

这个判断是对的，机制拆开看：

### 为什么套保一定是"反向"的

- 价格涨：LP 自动减持币（越涨币越少）-> delta 敞口变小 -> 要买回部分空头。涨了买。
- 价格跌：LP 自动增持币（越跌币越多）-> delta 敞口变大 -> 要加空。跌了卖。
- 套保交易天然买高卖低，系统性地亏给波动——和 LP 网格的"低买高卖"方向正好相反。

### 这不是 bug，是结构

LP 是卖出凸性（见 `case-toll-fee-pool.md` 损益不对称一节）。delta 套保做的事，就是把浮动的无常损失，换成一笔笔实付的 gamma 成本。套保网格亏钱 = 给保险交保费，天经地义。理论上"连续套保的成本"恰好就是 LVR——套利者从 LP 身上赚走的那部分，等于你自己套保时要付出去的那部分。

### 手续费不对称让它更差

- LP 收 fee 是被动成交（别人来吃你的单）。
- 套保再平衡往往是追价成交（taker），费率比 maker 高一档，还要付滑点。
- 一收一支之间，费率结构本身就是负的。

### 正确的问法

"套保亏钱"不等于"不该套保"。套保买的不是收益，是确定性：把左边尾部风险（单边暴跌）换成可预算的成本。真正的账是：

```
LP 策略净收益 = fee 收入 - 套保已实现亏损（gamma 成本）- 套保手续费滑点
```

三项都估得出来，这个策略才是可评估的。只做 LP 不套保 = 赌震荡；LP + 套保 = 花钱买平稳。哪个划算，要用历史数据按池子算，没有通用答案。

### 可验证动作

- 选一个池子，用历史价格序列回算：假如每偏离 X% 套保一次，累计套保成本和手续费是多少，同期 fee 收入是多少
- 这个回算脚本本身就是监控 Bot 之后的第二个数据工具（呼应"数据发掘是能力缺口"）

### 追问："套不上、不完全对冲，那还不如不对冲"（2026-08-05）

这句话一半很对，一半要修正：

**对的部分：伪对冲比不对冲更糟。**

- 山寨 LP 经常根本没有对冲工具：没有 perp、借不到币、最小下单量都够不上——这叫"套不上"，是执行约束。
- 用相关资产代理对冲（比如拿 ETH 空对冲山寨敞口）引入基差风险：代理可以不收敛，两边一起挨打。这不是对冲，是开了第二个风险头寸。
- 工具不存在的资产，LP 的 delta 就是裸露的——那就按裸露来管：仓位上限、止损线、环境假设监控。仓位管理替代对冲。

**要修正的部分：有合格工具时，"不完全对冲"不等于"不如不对冲"。**

- 对冲比例不是 0 或 1，是风控预算的旋钮。50% 对冲 = delta 敞口减半，套保成本也大致减半，风险调整后仍然占优。
- 真正反对部分对冲的理由不是"不完全"，而是 LP 的 delta 随价格非线性变化（gamma）：静态对冲比例很快就会跑偏，需要再平衡——成本又回到上一节的账上。
- 所以决策链条是：有合格对冲工具吗？没有 -> 不对冲，用仓位管。有 -> 算三行账（fee - gamma 成本 - 手续费），按比例对冲。算出来净额为负 -> 这个池子本来就不该做，对冲只是让它现形。

最后一条最值得记住：对冲不会让烂池子变好，它只会让烂池子的亏损从"突然的"变成"可预算的"。选池子仍然是第一层决策。

## 实战结论：LP 的世界观（2026-08-05，群经验）

一组来自实战的总结，和前面的机制推演互相印证：

### 1. LP 本质还是做多，套保意义不大

和上一节的账一致：套保成本（gamma + taker 手续费）大概率吃掉 fee，所以默认不做。例外是下面第 3 条的结构。

### 2. 牛市做 LP 最划算（例：去年 BSC 牛市）

注意这和"涨时跑输持币"不矛盾：

- 牛市 = 量价齐活：新池子不断、交易量爆炸、价格反复穿越——fee 极厚，LP 绝对收益很高，只是相对持币少赚。
- BSC 牛市这类 meme 季，本质就是"收过路费"的理想环境：爆量、缺池、剧烈波动、反复穿越四个入场条件全齐。
- LP 的对标从来不是"跑赢持币"，而是"fee 收入 vs 无常损失"这本账。牛市里这本账最容易为正。

### 3. 进阶结构：一份资金做 N 份 LP + 套保，只吃手续费

这是套保真正有意义唯一场景：用借贷/杠杆把一份本金放大成 N 份 LP 头寸，delta 套保对冲掉，纯收 fee。

- 收益 = N x fee；成本 = N x（gamma 成本 + 手续费）+ 借款利息。
- 这已经不是"LP 策略"，是资金效率游戏：fee 和成本的差额被杠杆放大，方向对了印钱，算错账加速亏。
- 属于"先证明单份账为正，再谈放大"的后期动作，共学期间只做研究不碰实盘。

### 4. 不缺流动性的时候，干不过无常损失

这句话指出了 LP 超额收益的真正来源：**稀缺性**。

- 池子深、LP 多 -> fee 被稀释 -> 摊到每份流动性上的 fee 盖不住 IL。
- 缺池、新资产、新链 -> fee 是对你提供稀缺流动性的补偿。
- 和"收过路费"的入场条件（缺池）、"做山寨"的场地选择是同一个逻辑：LP 要去流动性稀缺的地方，人多的地方没肉。

### 5. 最实用的风控：监控大额撤池

经验之谈，而且直接可执行：

- 大额撤池（尤其项目方/巨鲸地址）往往先于砸盘和 rug——LP 出逃是价格崩塌的先行指标。
- 监控信号：池子 reserve 突变、LP token 大额转出、项目方关联地址的撤池交易。
- 这正好挂进监控 Bot 的信号清单（backlog #8.5）：DEX 侧除了价差，第二类告警就是"我持有的池子出现大额撤池"。
- 技术上：EVM 侧盯 Pair 的 Burn 事件和 LP token Transfer；Solana 侧盯池子账户余额变化（Helius webhook 可用）。
