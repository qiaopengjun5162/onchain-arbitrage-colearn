# Jito BAM 拍卖时间 50ms→35ms 变更（2026-08-21 群分享）

> 来源：Jito 官方公告（群分享）｜ 核验：Helius BAM 文档 + Solana RPC getEpochInfo
> 归档日期：2026-08-21 ｜ 类型：基础设施变更（Solana 线直接影响）

## 变更内容

- **BAM 拍卖时间：50ms → 35ms**（Epoch 1020 生效）
- 背景：主网激活新 350ms 时隙时序（功能标志 Epoch 1019 激活，Epoch 1020 生效）
- **Jito Block Engine 拍卖时间不变：仍为 50ms**
- 官方提示：运行搜索机器人/执行策略/直接与 BAM 交互的系统需适配更紧凑的 35ms 窗口

## 核验（2026-08-21 晚）

1. **BAM 真实存在**：Jito 官方 2025-07-21 发布（Block Assembly Marketplace），Helius 有完整技术文档；分三阶段（Launch/Scale/Accelerate），目标 30%+ 质押覆盖率
2. **当前链上状态**：getEpochInfo → **epoch=1020, 进度 12.1%**——公告发布时是 Epoch 1019 末期，现在 35ms 窗口**已生效**（约 5.8 小时前开始）
3. BAM 是 Solana 区块构建架构重构：validator-driven 排序 → 私有/可编程/可验证的块空间拍卖（SEV-SNP 硬件加密虚拟化，AMD 处理器）
4. BAM 节点拍卖：intra-block 周期拍卖，块内 N 个 slot 均分 CU；Bundle 模拟→按 tip-per-CU 排序→选最高组合

## 对我们的影响（Solana 线）

### 当前 pipeline：不受影响 ✅
- `scripts/jito_bundle_pipeline.py`（D12 升级）走的是 **Jito Block Engine**（bundle 提交 + tip 自动定价 99 分位）
- Block Engine 拍卖时间保持 50ms 不变 → **我们现有 bundle 提交流程无需改动**

### 未来若接 BAM：需适配 ⚠️
- BAM 拍卖 35ms = 比 Block Engine 更紧凑——搜索机器人/策略要在这窗口内完成提交
- 影响点：tip 定价策略（35ms 内竞争更激烈）、提交延迟预算、多区域并行提交（<30ms 目标延迟）

### 战略含义
- BAM 扩展期（30% 质押 + 第三方节点开放中）→ 块空间拍卖机制还在演化
- 对我们盲套利/取证类工作：BAM 与 Block Engine 双轨并行期，关注哪个轨道的 bundle 成交率/tip 水平变化
- 350ms 时隙 = Solana 吞吐架构持续提速 → 套利延迟竞争升级（机器执行的必要性再 +1）

## 结论

- 基础设施变更已核验生效（Epoch 1020 进行中）
- **当前操作不受影响**（Block Engine 50ms 不变）；记录为 Solana 线环境变量，接 BAM 时再适配 35ms
- 无紧急动作；归档为环境变更日志
