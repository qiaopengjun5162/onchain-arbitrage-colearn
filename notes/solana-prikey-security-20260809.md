## 真实案例警示

### 1. Trust Wallet 供应链攻击（2025-12）
- 2025-12-24 Chrome 扩展 v2.68 更新被注入恶意代码，用户导入助记词即被窃取
- 12-25 报警（被盗 200 万 U）→ 12-27 扩大至 **700 万 U**，官方承认扩展被攻破
- **关键教训**：受害者用的是官方渠道更新——「我们以为安全的基础设施」不可信
- 「将私钥存储在钱包中真的安全吗？钱包官方如果想作恶，用户毫无防备」→ **私钥安全 = 技术问题 + 信任问题**

### 2. 剪贴板攻击
- 恶意软件监控剪贴板，检测到私钥/助记词格式字符串即外发
- 正常软件也会记录剪贴板到日志/远程

### 3. Coding Agents 新威胁（对本项目最重要）
- AI 代码工具（Copilot/Claude）对代码仓库有**完全访问权限**，且可访问网络
- 云端 AI 服务：代码仓库全部内容上传云端处理存储——**服务商能看到所有代码含敏感信息**
- 2025-08 GitHub Copilot 数据泄露（GCP 代理路由 bug，A 用户回答误发给 B 用户）：https://docs.cloud.google.com/support/bulletins#gcp-2025-059
- **即使本地部署 AI 也不安全**：clone 的项目里可以藏「给 AI 阅读的文件」，提示词诱导 AI 调 curl 上传本地文件——利用人类对 AI 的信任
- **呼应本仓库 AGENTS.md 铁律**：「不要在项目里保存私钥、助记词、API Secret、交易所 Token 或钱包截图」——因为 Codex/Hermes 两个 Agent 都有仓库全权限

## 私钥生成（密码学视角）

- 私钥 = 256 位随机数（ed25519），暴力破解计算上不可行（2^256 vs 宇宙原子数 10^80）
- **真正的威胁不是破解，是保管不当 + 生成环境不随机**：
  - 知名钱包低质量 RNG → 攻击者可猜出某时段所有私钥
  - 知名钱包官方主动埋毒，生成时外发私钥
- 大额资产建议：离线电脑 + 抛 256 次硬币生成（不依赖任何软件 RNG）

## 保管方案对比

| 方案 | 安全性 | 说明 |
|---|---|---|
| 软件钱包（加密存储） | 中 | 密码强度是薄弱点（123456/qwerty） |
| 纸钱包 | 中 | 完全离线，但物理安全（火灾/水/丢失） |
| **金属钱包** | 高 | 解决纸钱包物理问题，**最推荐物理冷存储** |
| 链下多签 naive（拆段） | **最不推荐** | 任意分片泄露即暴露部分信息，穷举 2^128 可恢复 |
| 链下多签 elder（加法分片） | 中 | 单分片泄露无信息，但**丢任意分片即永久丢失** |
| **Shamir SSS（门限签名）** | 高 | **推荐**：n 分片 k 阈值，少于 k 分片无法恢复；2-of-3/3-of-5；可容忍分片丢失 |

- naive 拆段反例：64 字符私钥拆 4 段，攻击者得 a+b 后只需穷举 2^128 组合
- elder 版：`(a + b) % N == c`，单分片无信息，但无容错
- Shamir 实现参考：https://github.com/libraries/pabtc/blob/master/example/sss.py

## 量子攻击

- Shor 算法可破解整数分解/离散对数——ECDSA(BTC/ETH) 和 ed25519(Solana) 都在攻击范围
- **BTC 有天然防护**：地址=公钥哈希，不签名就不暴露公钥（哈希抗量子）
- **Solana 没有**：地址就是公钥本身 → 无抗量子方案，须密切关注（Google 称 5-10 年）

## 对本项目的启示

1. **安全铁律执行**：私钥/助记词/API Secret/Token 绝不进仓库、不进聊天、不进长期记忆——Coding Agents 威胁是现实且持续的
2. **环境变量隔离**：本项目所有凭据在 `~/.hermes/.env`（不在仓库），脚本运行时读取——正确实践
3. **实盘资金**（若未来上）：钱包私钥用金属钱包或 Shamir SSS 冷存储，绝不进任何软件/仓库
4. **Solana 地址=公钥**：比 BTC 更脆弱，量子威胁下更要谨慎（不碰私钥的地址理论上是唯一防护，Solana 不可行）
