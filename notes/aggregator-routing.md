# 聚合器与路由：价值主张和批判性视角

日期：2026-08-05

## 群里的总结

> LI.FI 交易相较于直接在池子交易的好处是理论价格更优，它会聚合大多池子的流动性，线下计算最优执行路径。

## 价值主张（为什么对）

- 聚合流动性：单一池子深度有限，大单被自己的价格冲击吃掉；聚合器把多个池子、多个 DEX、多条链的流动性拼起来，等效深度更厚。
- 拆分执行：最优路径往往不是"找一个最好的池子"，而是把一笔单拆到几个池子分别成交，聚合器离线算这个拆分。
- 跨链抽象：桥 + DEX + 中间资产的选择打包成一条 route，用户不用自己拼。

## 两个必须保留的批判性视角

### 1. "理论价格更优"的关键词是"理论"

- 报价是请求时点的链下计算结果，上链执行时状态已变——回到零基础学习版的核心提醒：报价只是预计值，成交才是结果。
- 成本模型照算：桥费、Gas、滑点、最小到账、失败交易成本，一个都不能少。"聚合器报价更优"和"扣除成本后仍然更优"是两件事，小单尤其容易被固定成本（Gas、桥费）反杀。
- 验证方式：同一笔交易，同时拉聚合器报价和池子直报，再和实际成交对比，记录三者差异——这本身就是监控 Bot 可以加的一个字段。

### 2. 对套利者来说，聚合器报价是"市场共识价"

- 当所有人都用同一批聚合器报价时，报价本身就是共识——共识之内无价差。
- edge 在聚合器看不见或看得慢的地方：未被索引的新池子、私有流动性、报价更新延迟、它不支持的路径。
- 所以套利研究对聚合器的用法是双重的：执行工具（用它成交）+ 参照系（和它对比，找到它没算到的价格）。

## 补充：聚合器的适用场景边界（2026-08-05 群讨论）

> 同链或者对 CEX 肯定实时性差远了，跨链搬砖可以用，节省了很多接入成本，开箱即用。

这给出了聚合器的定位坐标：

- **不适合**：同链原子套利、CEX-DEX 对冲这类毫秒级竞争——聚合器多一跳报价请求和路由计算，延迟上先输。
- **适合**：跨链搬砖。自己接 N 条链的节点 + N 个桥 + N 个 DEX 的接入成本极高，聚合器把这些打包成一个 API，把「基建问题」变成「调参问题」。
- 推论：选执行工具前先问自己的策略在哪个延迟赛道。秒级以上的机会用聚合器没问题；亚秒级赛道聚合器只是参考价来源。
