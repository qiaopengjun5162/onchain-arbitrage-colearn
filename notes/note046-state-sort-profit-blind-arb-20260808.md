## 总纲：状态 → 排序 → 利润（三件事环环相扣）

- **状态**：池子价格/流动性/slot0/reserves 的真实链上状态
- **排序**：交易在区块中的位置（谁先执行、是否被抢跑）
- **利润**：扣掉 Gas、滑点、失败成本后仍为正的净利
- 配套铁律：**链上计算（或执行时读链）+ 私有提交通道，缺一不可**——前者解决「算得准/执行时仍成立」，后者解决「不被抢」

## 数据层：别指望聚合 API，自己算

| 痛点 | 典型表现 |
|---|---|
| 限流 | ~1 req/s，撑不住高频扫描 |
| 延迟 | ~100ms，机会窗口已过 |
| 本质 | 聚合方自己也是「读链+订日志」再加工 |

**成熟架构**：自建/专用 RPC → 订阅多池日志 → 本地维护状态（reserves/tick/liquidity/hot pools）→ 本地计算净利。
- eth_call 读 view 函数不花 Gas（只读模拟不上链）
- WebSocket/日志订阅负责「及时知道谁动了」，**最终以执行时读链为准**

**Hot Pool 流水线**：日志订阅 → 筛活跃池 → 新块对 hot pools 批量 eth_call → 有利润立刻构造 tx。前提：批量模拟需要自建/高配额 RPC。

## 两条执行哲学（对应 Paxon「staticcall 让节点帮你算」）

**链下模拟再上链**：适用机会稀疏、竞争弱、出块不极快；失效条件 = 高速链 + 多人抢同一路径。

**盲套利（执行时再算/再验）**：监测流动性变动 → 立刻上链 → 合约内读状态算利润 → 有利执行/无利 revert。失败交易多是设计结果不是 bug。

**价格实时性的真正来源**：来自执行时读链，不是订阅推送——订阅只回答「该不该去看」，成交瞬间的 slot0/reserves 才决定能不能赚。

## 链上算 vs 链下算：争议与统一模型

- **正方（bbvi）**：合约内算利润 + 早 revert，早失败只烧少量 Gas；V3/V4 区间最优求解 Gas 很重
- **反方（Mr.Lai）**：链上算往往吃不到利润，Gas 一高利润归零；常见模式是**链下算好路径/数量/sqrtPriceX96，上链 staticcall 读 slot0 校验，对不上就回滚**——链上不做完整利润求解，只做状态一致性守卫

**统一工程模型**：

| 层级 | 做什么 | 成本特征 |
|---|---|---|
| 链下 | 路径发现、最优数量、净利估算 | CPU 便宜，状态可能过时 |
| 链上轻校验 | slot0/tick/最小利润断言 | Gas 低，防过时 |
| 链上重计算 | V3/V4 区间最优求解 | Gas 高，仅当延迟收益 > Gas |
| 失败策略 | 尽早 revert | 用小失败成本换试错频率 |

调用栈辨析：合约读自己内部变量看不到对外查池的 call stack；出现对池子的 STATICCALL（slot0/getSlot0）说明在外部查询。Uniswap V4 的 PoolManager.unlock → unlockCallback 是 flash accounting 标准形态。

## 提交通道：私有通道 vs 满地失败交易

- 大量失败交易 ≈ 大概率没用私有通道（Flashbots Bundle 的失败 tx 根本不进公开区块）
- 经典 MEV 工作流：扫 Mempool → 发现机会 → 打包 Bundle → 提交 Builder → 进区块 → 提取 MEV

**路径发现时代划分**：Searcher 时代（扫 mempool 抢别人暴露的机会）→ Intent 时代（Solver 竞争）→ 盲套利（链上 staticcall 探测找没人盯的路径）。主网军备竞赛已数年，优先找活跃但未饱和的链。

## 闪电贷与「无本金」（对应 Paxon 第二论点）

- Uniswap V2/V3/V4 池子天然支持闪电贷式拆借/回调，常无额外协议费
- **「无本金」指不囤大库存，不指零成本**：仍有 Gas、失败率、竞争、机会密度

## 记账本位（e 本位 vs 对冲）

- e 本位：Gas 付 ETH、利润也是 ETH，按数量看不必对冲
- 对冲派：ETH 法币价波动吃掉利润购买力；活跃度低 ≈ 利润薄，更经不起单边行情
- 实操：先定记账本位（ETH 数量 vs USD），再决定套保

## 原理卡片（速查）

- **卡片 A**：eth_call/staticcall/view = 读链不花 Gas（本地或节点内模拟，不广播不改状态）；付 Gas 的是真正上链那笔 tx（含失败的）
- **卡片 B**：原子套利 + 最小利润守卫——多步 swap/清算/还款装同一笔交易，末尾 balance 增量 >= minProfit 否则 revert
