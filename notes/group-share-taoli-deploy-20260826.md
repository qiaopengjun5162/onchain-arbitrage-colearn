## 教程内容摘要（原文要点）

**接入流程**：打开交易页面 → Telegram 登录 → Settings → VIP0 免费直接用；付费等级需把设置页左上角 UID 发给 @aliez_ren 开通（推广话术：「可以说是从我这里看到的」）
- 添加交易所：填 API Key + Secret → Save 测试连接；「加越多交易所机会越多，一次性工作，我花了 2 小时」
- 设置页还有：通知、导入导出、界面选项；⚠️ 导出配置含敏感信息，**不要直接发群里/公开网盘**
- 本地运行 vs 服务器：纯前端 App 默认本地浏览器直接跑；网络调不通某所 API 或需固定公网出口 → 放远程服务器（一般日本 VPS，Vultr 推荐链接返佣，2C4G ≈ $24/月，vhp+Debian 12）
- 交易所 API 白名单 = 填**实际访问交易所的公网出口 IP**（本地运行填本机出口 IP；服务器部署填 VPS IP）

## 追加：API 最小权限配置 + 故障排查（2026-08-26 教程续段）

**API 最小权限（原文步骤，与安全铁律一致）**：
- 只开「读取 + 交易」权限，**不开提现**；交易所支持 IP 白名单 → 只允许固定出口 IP（本地运行=本机公网 IP；VPS=服务器 IP）
- 先独立子账户 + 小额资金测试；账户类型变化后**重新创建 API Key**
- Binance 示例：API 管理页创建「系统生成」API → 填受信任 IP → 按实际使用的现货/杠杆/合约产品开放权限 → 统一账户相关能力升级**前先停掉 Taoli 和所有自动交易** → 合约仓位模式设为「单向持仓」（按官方教程）

**故障排查（Failed to fetch）**：
- 症状：保存 Binance API 后 Failed to fetch → 大概率 **CORS 跨域**（纯前端应用直接发请求）→ 装官方推荐 CORS 插件 → 刷新页面重新 Save → 仍失败再查 API 权限/IP 白名单/服务器出口/交易所服务状态
- ⚠️ CORS 插件权限大：**给 Taoli 单独建浏览器 Profile**（不登录其他重要账户），不用时停用插件
- Binance API 地区限制：当前地区无法访问 → 教程建议日本 VPS（Vultr 推荐链接，返佣）

**判定**：全部与已有核验一致，无新信息量；「单独 Profile + 停用插件 + 无提现 + 白名单」是正确的最低风险姿势，若试用按此执行。Vultr 推荐链接照旧不点。

**再追加：单标签页 DB + 建交易对（教程续段2）**：
- `another tab is using it, so this tab cannot place orders` = P&L High-performance DB 同一时间只允许一个标签页记录交易 → 关掉占用 DB 的标签页再刷新
- 首次配置多所 ≈2 小时（API/账户模式/IP 白名单/跨域）——一次性工作，与 08-24 归档「单标签页 DB 占用」坑一致
- 创建交易对：交易页 Symbol/CA 搜索币种（教程用 TUT 示例）——TUT 是下一篇实战预告对象，我们已有 TUT 屠宰场完整档案可对照

**再追加3：交易页面说明（教程续段3）**：
- **同一币多个交易代码**（TUT 示例）注意区分：是否同一币 / 报价币种 USDT vs USDC / 市场类型（现货、全仓杠杆、逐仓杠杆、永续）/ 两边行情是否都读取成功
- 四种市场定义：现货=直接买卖；全仓杠杆=同杠杆账户资产负债共担风险；逐仓杠杆=保证金限单个仓位；永续=可多空+资金费+杠杆强平（注意杠杆和强平）
- **Add Pair 只代表识别了两个市场**：数量、方向、价差阈值、执行模式还需继续设置；**杠杆只能在交易所调整**（Taoli 里无法调）
- 判定：与库内认知互证——多代码辨识=多市场同币处理（我们的 scanner 已做）；「Add Pair≠可成交」= 08-23「大部分时间不成交」同构；永续资金费/强平=费率框架已有。归档完毕。

**再追加4：FAQ（教程续段4）**：
1. **价差多少才值得做**：无固定数字——费率等级/规模/深度/执行速度/资金费/借币成本因人而异；「盈利秘籍没人会说，只能用自己的真实费率和准备交易的数量计算 + paper 记录 + 小额实践」
2. **同 USDT 金额≠对冲**：看实际买卖币数、合约单位、市场类型（金额一样真实仓位可能不同）
3. **大价差无利润原因**：可成交数量太小 / 两边价格时间不同 / 手续费资金费吃掉 / 库存难低成本调回
4. **价差不一定收敛**：可能长期保持甚至扩大（流动性下降/交易暂停/限仓/交易所故障）

**判定**：四条全部与系列①核验表逐条互证（08-24 已核验），无新信息。FAQ1 的「用自己真实费率+数量计算+paper+小额实践」与我们方法论完全一致（真实费率优先于页面价差）。归档完毕，全教程链闭环。

## 开源核验：Taoli Tools Extension（2026-08-26 GitHub API + 源码审读）

**仓库事实**：`github.com/taoli-tools/taoli-tools-extension` — created 2025-09-30, **1 star / 4 forks**, **无 license**, README 24B 空壳, 全部代码 <4KB（background.js 2.4KB + content.js 0.6KB + injected.js 53B + manifest）

**代码行为核验（源码逐行审读）**：
- manifest：MV3，权限 `declarativeNetRequest` + `host_permissions *://*/*`；content_scripts **只注入 taoli.tools 和 localhost:5173**（不在其他网站活动）
- background.js：`EXTENSION_PROXY_FETCH` 消息代理 = 页面请求→扩展 fetch 代发（绕过 CORS），10s 超时，**请求透传、无存储、无第三方上传、无数据收集逻辑**
- urlFilters 覆盖主流交易所域名（binance/okx/bybit/gate/bitget/mexc/coinbase/backpack/apex/grvt/larksuite 等）= declarativeNetRequest 跨域放行规则
- action 点击只打开 taoli.tools

**判定**：
1. **扩展代码干净可审计**：标准 CORS 代理，key 由浏览器直接发交易所（请求头透传），扩展不碰不存不传——修正之前「完全闭源」的笼统表述
2. **「开源」名不副实打折看**：只开源了扩展骨架（4KB），**主应用（交易对/下单逻辑）仍闭源**；无 license = 法律上不可自由使用；1 star = 零社区审查
3. **风险实质不变**：主应用闭源 = 页面内逻辑不可审计；任何第三方工具的同等风险级。安全姿势照旧：只读 key + IP 白名单 + 无提现 + 独立 Profile + 不用时停用插件
