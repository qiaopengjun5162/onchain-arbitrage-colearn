# Meme 盘 Dev 出货手法拆解：从「藏仓-试探-分段卖出」到可量化信息差（2026-08-11）

> 来源：@hunterweb303（0x 哆啦A梦）推文，Pons 土狗盘 Dev `3929…ec4a` 链上取证（35 盘 + 105 盘两轮，Swap/转账/分润回执逐笔核）。
> 定位：信息差套利的状态机案例——**不预测 K 线，只判断「Dev 还在做盘还是已开始兑现」**，在受控大出货前进出。

## 一、Dev 出货状态机（可复用的动作序列）

| 阶段 | 动作 | 链上痕迹 |
|---|---|---|
| 1. 建仓 | 每盘先拿 ~3.8 ETH 建初始仓，不追买 | 主地址大额买入 |
| 2. 藏仓 | ~59% 库存转入「子钱包」（主地址直接转入的地址） | 主→子 转账；只盯发币钱包和 K 线的人看不到 |
| 3. 试探 | 小卖 0.4%~1% 库存，看外部买盘接不接、价格回不回 | 小额卖出簇 |
| 4. 主卖 | 盘子从本轮高点明显回落后，主钱包卖 ~40% 初始库存 | 大额卖出簇（样本 26/28 盘对上） |
| 5. 子钱包清仓 | 主卖之后子钱包清掉那 ~59% 库存 | 子地址卖出簇（23/25 盘对上） |
| 6. 分润 | 不只靠卖币：Locker 分润回执（35 盘 31 盘出现，Dev 实收 ~1.53 ETH WETH + 协议 ~0.92 ETH） | 分润转账 |

**关键认知**：出货不是一根大阴线砸到底，而是主/子/残余清理分段释放。只看单笔卖单会误判，把库存和地址串起来才能看见节奏。币价跌了 ≠ Dev 亏了（他有初始库存+已卖库存+子钱包库存+交易费四本账）。

## 二、为什么这是信息差套利（不是价差/不是赌博）

- 钱不是从 Dev 身上直接抢的（Pons V1 是现货池，没有做空入口），收益来自 Dev 维持盘面时持续进来的外部买盘。
- **Dev 给市场的是时间差**：什么时候还在维持盘面、什么时候小额试探、什么时候已进主卖——链上都有痕迹。吃的是「别人还没把主钱包、转仓地址、卖出、费用合成一本账」的时间差。

## 三、「四本账」监控（可工程化的哨兵指标）

1. 主地址+直接转仓地址还压着多少库存
2. 当前价格离这张盘自身前高多远
3. 最近 5/20/100 区块外部买卖的净流和笔数变化
4. 最近一次受控动作（建仓/试探/主卖）是什么、距今多久

只读已发生的链上数据，不预测下一根 K 线。回答的问题是：**这一刻买进去，下一次受控大额出货之前，有没有一条扣完费用后还能出来的路——有才允许进。**

## 四、进出规则（风险边界）

- **进场**：费后（池费+Gas+滑点）为正才进；每一笔成交重新报价
- **退出**：①费后正数就走；②受控大卖开始出现就走；③退出报价被吃掉也走
- **回本线**：不是买卖信号，只用来判断 Dev 风险偏好有没有变（例：3.95 ETH 初始仓卖回 5.8 ETH 但子钱包还压 59.6% 库存 → 他已回收风险，不代表他不再做盘）
- **不要当固定公式**：Dev 参数会换版本（「外部买入>0.10 ETH 先分仓」的规律在最后 32 盘只中 13 次）——可自动化 ≠ 永远同一套参数

## 五、与我们知识库的互证与落地

1. **信息差套利三步法同构**（`notes/information-gap-arb-essence-20260810.md`）：赚钱=信息差套利；本文=「Dev 状态」这个信息差的完整取证样例
2. **链上取证方法论**（`onchain-address-forensics` skill）：主钱包→子钱包→分润地址的地址图谱串联，正是我们横纵分析法的应用（把 0xd712/888BMM 那套手法搬到 meme Dev 上）
3. **哨兵架构同构**：四本账 = 4 个监控指标（库存/距高点/净流/动作间隔），和我们 Solana 执行层 5 哨兵、无套利带雷达同一套「只读发现，人扣扳机」模式
4. **可工程化**：候选「Dev 行为哨兵」——监控高频发盘地址的建仓/转仓/试探/主卖动作簇，触发「受控大卖出现」告警。接 `scripts/listing_monitor.py`（新盘发现）或独立脚本

## 七、玩家侧补丁：妖币埋伏观点（@nine_DeFi，2026-08-11 归档）

同一状态机的另一面——庄家侧是「Dev 怎么出货」，玩家侧是「什么时候埋伏」：

- 阶段判断：妖币热潮中后段 → 涨幅榜轮转快、断头台拉闸多、情绪面拉盘主导 → 追涨幅榜=接盘位
- 建议动作：埋伏「高控但未异动」+ 低市值壳币（~5M 市值）+ 回踩追龙头
- **可验证假设**：「市值越接近 5M 越难亏钱（只要不偷偷增发）」——这可以量化：对 Solana 链上 ~5M 市值的币做 cohort 分析（增发监控 + 7/30 天存活率 + 收益分布），和我们的 Dev 状态机（是否已进入主卖）结合，把「难亏」改成「在 Dev 出货前离场」
- 反身性提醒（评论区）：「你能想到的，庄家也早已料到」——埋伏策略拥挤后，Dev 会提前制造假异动/假洗盘收割埋伏者；这正是「别把 Dev 当固定公式」的玩家版
- 与信息差三步法同构：埋伏 = 信息差（Dev 还在做盘的痕迹）+ 时间差（出货前离场）
