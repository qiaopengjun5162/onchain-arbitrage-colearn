# Mempool 与排序：套利者面对的两难格局

日期：2026-08-05（群讨论）

## 群友原话

> 有公共 mempool 的链，被 builder 和 MEV bot 给把持的死死的；没有公共 mempool 的链，私有排序器又是个黑盒，被 front/backrun 了都不知道为啥。我的感官是正面竞争太激烈了，得打差异化。

## 拆解：两种链，两种死法

### 有公共 mempool（典型：Ethereum 主网）

- 你的交易在被打包前对所有人可见，等于明牌。
- 有成熟的基础设施（builder、searcher、Flashbots 生态）专门盯着 mempool 里的套利交易，用更高的出价（priority fee / bribe）抢跑或夹击。
- 竞争激烈但**规则透明**：你知道对手是谁、用什么手段，也有防御工具（私有交易通道、anti-MEV RPC）。

### 无公共 mempool（典型：Solana、各 L2 私有排序器）

- 交易直接进入排序器/leader，外部看不到排队过程。
- 没有公开的抢跑市场，但排序器自己是黑盒：交易被插队、被丢包、被夹，你拿到的只有「成交/没成交」的结果，归因困难。
- Solana 的特殊性：没有 mempool 但有 Jito 的 bundle 拍卖，抢跑以另一种形式存在。

## 对我们的策略含义

「正面竞争太激烈，得打差异化」——这句话和共学核心叙事完全一致（速度/基建卷不过，找市场差/规则差/信息差）。落到 mempool 层面：

1. **不在排序层的红海里拼速度**：原子套利、三明治防御这类拼 builder 关系的赛道，个人没有 edge。
2. **差异化的本质是找排序竞争还没卷到的地方**：新链、新池子、跨链路径（多一次排序就多一层复杂度，竞争者指数减少）、CEX-DEX 之间（跨了两个排序体系）。
3. **防御优先于进攻**：不管在哪个链，先用私有通道/防 MEV RPC 保护自己的交易（比如群友提到的 Binance Wallet API 自带防 MEV），再谈找机会。被 front-run 掉的不只是利润，还有你对策略有效性的判断——你以为策略不行，其实只是被夹了。

## 捆绑原子性：让 tx 和 target 绑在一起（2026-08-06 补充）

Paxon 群讨论补充：**gas 高让 target tx 和你的 tx 绑一起，要么都不成交要么都成交，出来的结果就是全部同区块，其实很多都是相邻交易。**

### 机制拆解

**传统 gas 竞价（以太坊）**：
- 比 priority fee 高低决定排序
- 问题：你出价高只是排序靠前，**target tx 可能没进同一区块**——前腿买了，后腿没跟上，白亏

**Bundle 绑定（Flashbots / Jito）**：
- 把前腿 tx + target tx + 后腿 tx 打包成一个**原子单元**提交
- 要么全部进区块，要么全部被拒 → **消除单腿风险**
- 结果是所有 tx 同区块、**相邻执行**（这就是"相邻交易"的由来）

### 为什么"相邻"重要

三明治攻击的利润完全依赖顺序：
```
前腿买（frontrun）→ target 大额买（推高价格）→ 后腿卖（backrun）
```
- 不是同区块 → target 可能被别人夹走，或价格在你后腿前已回落
- 同区块但不相邻 → 中间插了别人的交易，价差被吃掉
- **同区块 + 相邻 = 锁定价差**

### Solana 上的对应

- Solana 无公共 mempool，但 **Jito Bundle** 提供同样的原子提交机制
- searcher 把多个 tx 打包，附 tip 竞拍 leader 的打包权
- 这是 Solana 上做三明治/backrun 的基础设施（D11-D13 要学的）

### 对策略的含义

- 原子性是把"多腿策略"变成"单笔交易"的关键——前腿亏风险被消除
- 但 bundle 提交本身有成本（tip/贿赂），且 leader 有最终决定权
- 个人开发者用 bundle 做套利，本质上还是在排序层竞争，卷度没有降低

## L1 vs L2 排序机制（2026-08-07 群分享 + Hermes 精确化）

### 分享原文要点（Paxon）

1. **以太坊 L1**：PoS 共识，每 12 秒随机挑一个验证者作为出块者（Proposer），由它决定区块内交易及顺序。不存在固定的"排序器"角色。
2. **Layer 2**：为追求高 TPS 和毫秒级延迟，设计排序器（Sequencer）作为链下"交易收货员"：快速接收交易、按顺序排队、给亚秒级"软确认"，最后打包成批次（Batch）提交 L1 结算。

### Hermes 精确化补充

**L1 排序**：
- "随机挑选"实际是**按 stake 权重抽签**（不是等概率），随机源是 RANDAO（不可预测性保证公平）；只有被抽中的验证者能对当前 slot 排序——**排序权 = MEV 提取权**（对应 Greenfield 文章"优先访问共享状态"的结构性价值）。

**L2 排序器（有谱系，不是只有一种）**：
| 类型 | 谁排序 | 例子/状态 |
|---|---|---|
| 中心化排序器 | 单一运营方 | 早期 Optimism/Arbitrum 标准部署（已演进） |
| 去中心化排序器 | 排序器网络 | Espresso、Radius 等共享排序器 |
| Based Rollup | 排序权还给 L1（L1 proposer 顺带排 L2） | Based rollup 叙事 |

**中心化排序器的风险**（对套利者的直接含义）：
- 单点故障 + 审查能力：排序器可以丢你的交易、重排、插入自己的交易（排序器自己提取 MEV）
- 应对机制：**forced inclusion（强制包含）**——用户可以直接把交易发 L1 绕过排序器（慢但保证不被审查）

**软确认 ≠ 最终确认**：
- 排序器的"软确认"只是承诺，最终性以 L1 结算为准；批量提交 L1 前可被回滚/重组
- 跨链套利若基于软确认做决策，承担"到 L1 后被回滚"的风险

### 对套利策略的含义

1. L2 排序器是**比 Solana 的 Jito 拍卖更不透明的黑盒**：没有公开抢跑市场，被插队/被夹难以归因。
2. L2 上 DEX 套利：延迟低但排序权集中，竞争者是排序器本身 + 专业 searcher。
3. 跨链路径 = **多一个排序环节** = 复杂度上升 = 竞争者指数减少——延续本笔记"打差异化"的结论。
4. 防御优先：L2 上优先选有 forced inclusion/抗审查能力的路径；理解每条链的"排序透明度"再决定投入。
