## 一句话

Agent 执行能力涨了，但「协作带宽」（信息在成员/Session/分支/权限域之间被正确继承的能力）没涨——团队记忆把任务轨迹、项目知识、代码结构、工作方法转成**可治理的记忆资产**，让「任何错误只犯一次」。

## 核心概念（人话版）

- **协作带宽** = 单位时间内，在正确权限边界下，能被相关人或 Agent 正确理解并直接用于任务的有效上下文。不是消息数量，是「找得到 + 看得懂 + 有权用」。
- **OPC（One-Person Company）**：一个人 + 多个 Agent 的组织模型。Carta 数据：2025 年新公司 36% 单一创始人（2024 年 31%）。
- **三层 AI 组织架构**（孙天祥/日行迹智能演讲）：顶层治理信息边界，中层人机任务现场，底层可继承组织资产。
- **Spec 与团队记忆的分工**：Spec 让一次任务状态可表达，团队记忆让验证过的状态可继承。Spec 不回答「类似问题过去发生过吗」。

## 产品结构：四类资产 × 分层装配

**四类资产**（对应四个问题）：

| 资产 | 保存什么 | 典型问题 |
|---|---|---|
| Chat Memory | 背景、约束、决定、偏好、历史交互 | 当时为什么这样判断？哪些路径试过？ |
| Wiki | 产品知识、架构、规范、Runbook、历史结论 | 项目已经知道什么？规则在哪？ |
| CodeGraph | 符号、文件、调用、依赖、影响路径 | 改这个接口影响哪些模块？ |
| Skill | 可重复执行的方法、工具调用、边界、验证规则 | 这问题通常怎么处理并验收？ |

**内容分层 L0→L3**：L0 原始对话（高保真低密度）→ L1 Atom（事实/约束/决定）→ L2 Scenario（场景化记忆块）→ L3 Core/Persona（长期画像）。高层减少阅读量，低层防止抽象失真——**抽象与证据必须同时保留**。

**路由分层**：身份/ACL 过滤（无权限不进入候选）→ 固定绑定（组织事实不被相似度覆盖）→ 浮动召回（BM25 精确 + 向量意图，RRF 融合）→ 上下文装配（Token 预算）。**渐进式暴露**：Prompt 只告诉「有什么」，工具调用按需取细节。

**关键设计**：资产跟着 **Team** 走（不是 Agent），框架中立（与宿主解耦，记忆才真正属于团队）；「完整属于资产池，相关属于当前任务」。

## 数据与评测（自报，需谨慎看待）

- **2,600 Session → 5,081 Task**（Session ≠ 单一任务）；48,114 候选 Pair → 22,361 canonical → 强关系仅 **231 条**（same_work_item 42 / same_problem 135 / reusable_sop 54）。
- **洞察：相关 ≠ 可复用**。38% 精确类型正确率但 95% 存在具体关系——模型容易发现「有关系」，难判断「是同一问题还是可迁移 SOP」。→ 资产需要置信分层（强/弱/背景），不能只有保留/删除。
- **卡点分析 2,203 个**：逻辑返工 1,350（61%）>> 缺上下文 269。→ 记忆不能只做「找资料」，要保存决策理由、失败路径、适用条件。
- **SWE-bench 相关 Case**：完成率 60% → 80%（绝对 +20pp）。
- **SWE-bench Top50 超长难**：通过率 17% → 20%，成本 $887.64 → $717.78（-19%），turn 数 -19%。
- 作者诚实声明：不是部署后全提升 20pp；需固定评测子集、置信区间、负迁移测试；内部审计用模型完成非人工金标。

## 六条设计原则（可迁移到任何团队记忆体系）

1. 记忆目的不是保存历史，是**继承状态**。
2. 资产价值 = 降低下一次任务的不确定性。
3. 抽象与证据必须同时保留（只有抽象没证据→无法判断可信度）。
4. 资产原子化、可组合、按任务装配。
5. 记忆必须有生命周期（Review/降权/锁定/过期/删除，人负反馈改变路由）。
6. Memory 与模型/Agent 框架解耦。

## 与我们的体系对照（Hermes 个人版已在实践同一套）

| TencentDB | 我们的对应物 | 差距 |
|---|---|---|
| L0 原始对话 | Hermes `session_search`（SQLite 全量会话） | ✅ 已有 |
| L1 原子事实 | Hermes memory（稳定事实） | ✅ 已有 |
| L3 稳定认知 | Hermes skills（流程方法论） | ✅ 已有 |
| Wiki | 共学知识库 notes/ + daily/ | ✅ 已有 |
| CodeGraph | ❌ 无 | 个人项目规模下收益低，暂不需要 |
| 权限/ACL/治理 | ❌ 单人场景不需要 | 多 Agent 协作（qintopia）时值得借鉴 |

**结论**：架构思想被我们实践验证过（「逻辑返工>缺上下文」正是我们踩过的坑：Codex 并行覆盖、compliance 重跑）；TencentDB 的 Hermes 插件要跑 Node sidecar + 向量库，个人盘太重，**不装**。价值在于：若给 qintopia 设计团队记忆模块，L0-L3 分层 + 四类资产 + 权限治理是现成蓝图（可扒 MemoryCore/ 结构）。
