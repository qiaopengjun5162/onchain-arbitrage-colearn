> Week 2 交付物 ③(假设验证)　|　被验对象:[收费站套利法.md](收费站套利法.md)(共学群分享)

## 0. 先说结论

**假设不成立,而且差得很远。** 用真实历史数据回测,同一套设置在两种行情下:

```
COAI(币价 +2.6%)      手续费 +4.29 USDT    存货 ±0          净 −0.7 bps
币安人生(币价 −20.1%)  手续费 +180.60 USDT  存货 −1,157.40   净 −981.8 bps
```

第二个案例里,**手续费只覆盖了亏损的 15.6%**,投 10,000 USDT 亏掉 982 USDT。

而且注意:第二个案例按原文的标准是**开张非常成功**的 —— 65% 的时间有流量、手续费收了 180 USDT。**赚了手续费,依然巨亏。**

## 1. 先搞懂这个玩法在做什么

### 1.1 什么是「集中流动性」

传统 AMM(Uniswap V2)里,你存进去的钱铺在 **0 到 ∞** 的整个价格轴上。绝大部分钱永远用不到 —— 没人会在 ETH 涨到 100 万美元时来跟你成交。

Uniswap V3 让你指定一个**价格区间**,钱只铺在这段里。同样的钱,在这段区间里的深度就厚得多,赚的手续费也多。代价是:**价格跑出区间,你就一分钱不赚**。

### 1.2 单边存入 = 一张限价单

这是理解整个玩法的钥匙。

假设某币现价 **1.00 USDT**,你把区间设在 **0.80 ~ 0.98**,并且**只存 USDT**。

因为区间完全在现价**下方**,此刻它是 100% 的 USDT。只有当币价跌进 0.98 以下,才会开始有人拿币来换走你的 USDT。

> **这等价于:你在 0.80~0.98 之间挂了一串限价买单。**
> 区别只是你还额外收一笔手续费。

原文说的「相当于在现价下方挂了一张收费 5% 的买单」——**这句话完全正确**,而且是全文最重要的一句。但原文没往下推一步。

### 1.3 关键问题:谁是你的对手方

原文的框架是「机器人经过你的池,交过路费给你」。听起来你是收费站老板。

**但机器人为什么要经过你的池?**

原文第二节自己回答了:「机器人只比较最终到手金额……剩下的利润仍然为正,它才会成交。」

也就是说 —— **机器人只在「跟你交易对它有利」的时候才来。** 它在外面买到便宜币,卖给你换走 USDT,赚走的就是你的报价和外部市场之间的差。

```
它赚的钱  =  你的报价 与 真实市场价 的差    ← 从你口袋里出
你赚的钱  =  手续费                        ← 从它口袋里出
```

**这两笔钱方向相反,净值可正可负。** 原文只写了第二项。

这个损失有正式名字:**LVR(loss versus rebalancing)**,中文常译「相对再平衡损失」,直白说就是**逆向选择** —— 你系统性地在被信息更快的人挑着打。

> 换个比喻:你不是收费站,你是**外汇兑换窗口**,而排队的全是知道下一秒汇率的人。
> 手续费是你的点差收入,被挑着换是你的成本。生意能不能做,看点差够不够覆盖被挑着打的损失。

### 1.4 为什么在新币上特别凶

单边 USDT 挂在下方,**成交的时刻正是币在往下砸的时刻**。

对一个刚爆量的新币,归零是**基准路径**而不是尾部风险。所以这个策略在结构上是:
**系统性地把稳定币换成正在下跌的币。**

原文把这条写在第八节风险清单里(「单边行情会让仓位逐渐变成目标币」)—— 但它不是风险之一,**它是主要成本项**。

## 2. 怎么验:把它变成可计算的东西

要证伪一个假设,先得把它写成能算的式子:

```
净收益 = ① 手续费收入
       − ② 存货盈亏(撤池拿回的东西,比投进去的少多少)
       − ③ gas
```

三项都能从历史数据算出来:

| 项 | 数据来源 | 怎么算 |
|---|---|---|
| ① 手续费 | 逐小时成交额 × 费率 × 我的份额 | 只在价格落在我区间内的小时才计 |
| ② 存货 | 逐小时价格 + V3 数学 | 用 (L, 区间, 当前价) 精确算出仓位构成 |
| ③ gas | 手动估 | 建池 + 撤池 + 换回稳定币 |

**这套算法不含任何拟合和猜测** —— V3 的仓位构成完全由「流动性 L、区间 [Pa,Pb]、当前价 P」四个量决定,是精确公式。


应该看到三行 `✓`。

### 第 2 步:先看看高费率池到底有没有流量

在做复杂回测之前,先问个更基础的问题:**高费率池能不能拿到流量?**

Base 上 WETH/USDC 四个费率档,24 小时实测:

```
fee100  (0.01%)   $3,030,371    35,727 笔
fee500  (0.05%)   $7,691,203    13,843 笔
fee3000 (0.30%)  $31,456,452    19,523 笔
fee10000 (1.0%)       $9,249        78 笔   ← 高费率档几乎吃不到流量
```

**1% 档一天只做了 9,249 美元,是 0.3% 档的 0.03%。**

这不能直接否定收费站(它打的正是「没有低费率竞品」的场景),但它说明:**聚合器路由只认最终到手金额,费率一高立刻被绕开。** 你的池能有流量,唯一原因是当时没有更便宜的路 —— 而这个条件会自我毁灭。

```
③ gas                  -5.00 USDT
   净收益             -981.80 USDT   **-981.8 bps**
```

**这一段值得逐行读:**

- **88/135 小时在区间内(65%)** —— 按原文标准,这个收费站**开张得非常成功**

- **撤池拿回 0 USDT + 17,219 个币** —— 你的 USDT **全部**变成了已经跌 20% 的币

> 成交越频繁 → 说明价格穿越越剧烈 → 你被填的单越多 → 存货亏得越狠。
> **「生意好」和「亏钱」在这里是同一件事。**

## 4. 区间扫描:一对无法调和的矛盾

```bash
python3 lp_backtest.py --chain BNB \
  --pool 0x4610464356ba6bba15eec558619d84b72fea260f \
  --capital 10000 --since 2026-07-29T08:00:00Z --hours 168 --sweep
```

```
              区间       在区间小时     穿越          手续费          存货盈亏      净收益bps
       [-5%,-1%]          42     22        +6.37         +0.00        +1.4
      [-10%,-2%]          19     12        +4.38         +0.00        -0.6
      [-20%,-2%]          19     12        +4.29         +0.00        -0.7
      [-30%,-5%]           1      2        +0.42         +0.00        -4.6
     [-50%,-10%]           0      0        +0.00         +0.00        -5.0
     [-20%,-10%]           0      0        +0.00         +0.00        -5.0
     [-40%,-20%]           0      0        +0.00         +0.00        -5.0
```

**只有最窄的 `[-5%,-1%]` 是正收益(+1.4 bps),稍微放宽就转负,再宽就是 0 小时在区间内。**

最后三行的 `0 小时 / 0 手续费` 是收费站**最常见的失败模式** —— 不是亏钱,是**根本没开张**,资金白占着。

于是矛盾出现了:

```
要有流量  → 区间必须贴近现价(窄)
不被砸穿  → 区间必须远离现价(宽)
```

**这两个要求直接冲突,没有中间解。** 窄区间有流量,但也最容易被一根大阴线扫穿变成全仓接盘。

## 5. 我在验证过程中踩的三个坑

这部分比结论更有用 —— 都是能迁移到别处的。

### 坑 1:V3 的 liquidity 是**原始整数单位**

第一次跑出来手续费是 `+0.00`,但明明显示 19 小时在区间内。

原因:我用「10000 USDT」这个人类可读金额反解出流动性 L,再去和 subgraph 的 `liquidity` 字段比份额。但 **V3 的 L 定义在原始整数单位上**(含 decimals),池子的 L 是 10¹⁸ 量级,我的是 10⁴ 量级 —— 份额被算成 ~0,手续费自然全是 0。

**这是这个项目里第二次栽在单位上**(上一次是 `pool_price.py` 把价格方向标反,bps 算出天文数字)。

> **可迁移的一条**:凡是「我的量」要和「链上的量」做比值,先确认两边是不是同一个单位制。

### 坑 2:价格方向搞反

找「跌得最狠的币」时,我直接拿 `token1Price` 排序。但池子里 token0/token1 的顺序是**按合约地址大小定的**,不是按你的直觉:

- `COAI/USDT`:USDT 是 token1 → `token1Price` = USDT 每个币 ✓ 方向对
- `USDT/币安人生`:USDT 是 token0 → `token1Price` = 币每个 USDT ✗ **方向反了**

结果我第一版排出来的「跌得最狠」榜单里,有一半其实是**涨得最狠**的。按稳定币计价统一之后,榜单完全变了。

> **可迁移的一条**:AMM 里的 token0/token1 没有语义,只有地址大小。
> 每次都要显式判断哪边是你要的计价单位。

### 坑 3:数据本身会骗你

`CAT/WBNB` 报出 **425 亿美元累计成交额、1.6 万 TVL**。资金周转率 250 万倍。这不是繁荣,是刷量。

脚本现在会自动标记 `成交额/TVL > 100,000` 的池。

> 这条呼应你之前那条铁律候选:**对上游数据做不变量检查,API 返回 200 不代表数据合理。**

## 6. 这个回测的局限(必须说清楚)

诚实地讲,以下几点会影响结论的精度 —— 但**都不足以翻转结论**,因为差距是 6 倍量级:

1. **手续费份额是近似的。** 我按「我的 L /(池子活跃 L + 我的 L)」分摊,而 `liquidity` 字段只是**当前 tick** 的活跃流动性。真实 V3 流动性按 tick 分布不均,在分布很偏的池上会有偏差。
2. **只测了两个池、一段行情。** 样本远远不够下普适结论,只能说「在这两个案例里不成立」。
3. **没有模拟动态调仓。** 原文暗示可以「流量结束以后撤出来」,而回测是买入并持有到期末。主动管理**可能**改善结果,但那要求你比机器人反应快 —— 而这个玩法的出发点恰恰是「卷不过机器人」。
4. **subgraph 的 TVL 不可信**(实测比链上真实余额虚高 3~6 倍),所以脚本**完全不用 TVL 做计算**,只用价格、成交额、手续费、流动性。
5. **不含新币特有的风险**:合约后门、抽池、转账税。这些只会让结论更差。

---

## 7. 结论

**不建议实盘。** 不是因为机制假 —— LP 赚手续费是真实生意 —— 而是:

1. **主导项是存货亏损,原文没算。** 实测手续费覆盖率只有 15.6%。
2. **「有流量」和「不被砸穿」直接冲突。** 区间扫描显示没有中间解。
3. **前提「缺池」会自我毁灭。** 一旦真赚钱,就有人开更便宜的池抢走流量。
4. **和你的主线正交。** 你的差异化在跨链清算 / 长尾链清算 / 经济漏洞型 MEV,靠的是 Sonic 清算实盘 + 合约安全背景。BSC 新币做市这两样一样用不上。

### 原文里值得肯定的部分

不是全盘否定,这几处是扎实的:

- **第六节「怎么判断收费站开张了」** —— 看聚合器 Route 有没有收录、看 Swap 发起方是不是路由/合约地址且短时反复双向。方法论正确。
- **先建探针池小额验证** —— 直觉完全对,和铁律 3 一致。
- **净利润 = 最终换回稳定币 − 初始投入 − Gas** —— 这个公式**本身是对的**,而且是闭环/token 口径,比很多人强。问题是它只能**事后**算,给不出事前判断。

---

## 8. 沉淀

1. **「谁是我的对手方」是评估任何做市/被动策略的第一个问题。** 如果对手方永远比你信息快,你收的费就是你的全部收入,而你的损失没有上限。
2. **收入项和成本项可能由同一个原因驱动。** 这里「手续费多」和「存货亏损大」是同一件事的两面。看到一个策略只宣传收入项时,先找它的成本项是不是同源。
3. **把别人的策略变成可计算的式子,是最快的证伪方式。** 从看到这份文档到跑出结论,全程没花一分钱。
