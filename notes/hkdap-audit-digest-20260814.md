# HKDAP 合约审计 digest：香港首个持牌港元稳定币（2026-08-14）

> 来源：BlockSec 公众号审计报告 https://mp.weixin.qq.com/s/c51RuHUkoau-4rwlipHWWA
> 对象：HKDAP（Anchorpoint 发行：渣打香港 + HKT + Animoca；HKMA 稳定币牌照 36 选 2；2026-08-12 第一阶段上线以太坊主网）
> 定位：稳定币套利方向事件标记 + 合约审计取证方法论沉淀

## 一句话

香港首个持牌港元稳定币 HKDAP 的合约审计：**KYC 撤销控制失效（fail-open）、治理单签化、transfer 路径绕过、主网部署 debug 版本**——13 条发现，结论是「未达生产可用水平」；根因 = 弃用成熟组件全部手写。

## 审计发现（13 条浓缩）

| # | 发现 | 机制 | 影响 |
|---|---|---|---|
| 1 | KYC isActive 死代码 | 循环条件 `0 > N` 永不执行 + `==` 误用为 `=`；unregisterVerifier 不改状态 | 被注销验证方名下钱包照常转账（fail-open） |
| 2 | KYC proof 被丢弃 | `_checkKYCProof` 形参无名、函数体不读 | 链上不校验 KYC 证据，全凭链下验证方自觉 |
| 3 | 免检额度可拆单绕过 | freeTransferLimit 只判单笔不累计 | 大额拆多笔即绕过 KYC 门槛 |
| 4 | 高危操作单签 | 增发/冻结/KYC 停用 = 角色 C 单签；暂停/销毁 = 角色 D 单签；拉黑 = 角色 F 单签 | 一个私钥即可增发+销毁+冻结 |
| 5 | 升级无时间锁 | A+B 双签但凑齐即在同一交易执行（实测相邻两区块 12 秒） | 无双签人独立复核窗口 |
| 6 | 角色高度集中 | 一个地址身兼 6 角色；审计角色与执行角色同属 23 人组 | 私钥丢失 = 增发/冻结/KYC 同时失控 |
| 7 | 撤销不即时 | 已计票签名不因角色撤销重新校验 | 事后撤销收不回已投的票 |
| 8 | transfer/transferFrom 不一致 | 白名单在 transferFrom 提前 return 绕过 isActive | 同一收款人走不同函数合规要求不同 |
| 9 | 部署 debug 版 | console.log 留在代理 fallback（每笔交易执行）；代理注释与行为相反 | 永久多余 gas 开销 + 信任边界误导 |
| 10 | 角色哈希不一致 | ELEVATED_RISK 常量名同、keccak 字符串不同 → 两个角色 | 权限模型和设计不符 |
| 11 | 测试套件上传 | 验证包传 117 文件含测试用例；优化器 0 次 | 未走生产发布流程的痕迹 |
| 12 | 升级历史可还原 | 4-28 部署 → 7-10 升级（0x8ff12f→0xe42d38），未修复任何缺陷 | 双签人现已轮换，注册表认不出 |
| 13 | 销毁记账错位 | destroyBlackFunds 发 Transfer(→address(this)) 但余额不入账 | 索引器事件重建总供应与链上分叉 |

## HKMA 指引冲突（Part 2）

- 条款 6.5.3 高危操作不能单方完成 → **违规**（单签 + 无时间锁，速率上限缓解不替代多签）
- 条款 6.5.4 职责分离 + 即时撤销 → **违规**（6 角色集中 + 撤销不即时）
- 条款 6.5.5 每次变更审计 → **不达标**（缺陷留在部署代码）
- 条款 2.2.3 冻结/销毁足额背书可对账 → **存疑**（事件与余额账目分叉）

## 取证手法沉淀（可复用，接 evm-arbitrage-tx-forensics）

1. **角色注册表枚举**：读 HybridControlledAuthority（0xa7287701…）存储，枚举全部角色 + 持有者 + 授权范围
2. **authorizationMatrix 直读**：每个操作的签名门槛（单签/双签）从治理合约矩阵读出，不是看文档
3. **升级历史还原**：proxy implementation 时间线（部署 → 每次 upgradeTo 区块 + 签名人），且注意**角色轮换会让旧签名人从注册表消失**——查历史只能靠交易记录
4. **存储槽读公开数据**：公链上「只读角色锁」形同虚设（底层存储人人可读）——审计视角：任何"看不见"的数据都可以直接读槽位
5. **事件 vs 状态对账**：销毁事件指向 address(this) 但余额为 0 = 索引器陷阱——链上结论必须以状态为准，事件只是线索

## 对我们研究方向的意义

- **稳定币套利方向**：新持牌稳定币上市 = 事件（上币/折价/流动性建设期）；但 HKDAP 是 **B 端合规币，DEX 流动性未知** → 标记观察，不投入（research-backlog 稳定币套利项下）
- **判断力**：「牌照和文档怎么写并不作数，只取决于代码」= 宣称 vs 链上证据，永远信后者（gross-vs-net 同构）
- **风险模板**：任何「持牌/受监管」新币，先查是否手写 ERC-20/无时间锁/单签——BlockSec 这 13 条就是现成 checklist
