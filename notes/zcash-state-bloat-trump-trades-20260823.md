## 一、Zcash 屏蔽池数据爆炸问题（Paxon 观点核验：✅ 正确）

**Paxon 原话**：「zcash 自己就有数据爆炸的问题——它的 nullifier 和 UTXO 会无限增长，且所有 UTXO 都不能被丢弃」

**核验结果（技术分析）**：

1. **nullifier 集合无限增长**：Zcash 屏蔽交易（Sapling/Orchard）每笔 spend 产生一个 nullifier（防双花标识），**必须永久保留**——因为证明「没花过」需要检查 nullifier 是否已存在。nullifier 集合随交易量线性增长，**无法修剪**
2. **note commitment tree 同样增长**：屏蔽池的 note 承诺树（commitment tree）每笔新 note 追加一个叶子，全节点必须保存整棵树（Merkle path 验证需要）
3. **UTXO 不能丢弃**：屏蔽池的 note 一旦创建就永久有效（除非被花费），不像透明 UTXO 有「找零合并」的自我清理——**屏蔽池 = 只增不减的数据结构**
4. **对比透明链**：BTC/ETH 的 UTXO/account 状态虽也增长但有「花费即删除」，Zcash 屏蔽池是「创建即永久」

**为什么这是难题**：隐私要求（不暴露哪个 note 被花）导致无法用普通 UTXO 修剪；所有全节点要存完整 nullifier 集合 + commitment tree → 状态膨胀。社区提案 Ztreexo（accumulator 压缩 nullifier 集合）仍在研究，未落地。

**对我们的意义**：任何「隐私链/屏蔽池」类项目评估时，**状态增长模型**是核心考量（不是共识机制/代币经济学）——隐私 = 状态只增不减，长期运行成本随使用量线性上升。与 Layer1 扩容叙事（Solana 状态租金、以太坊状态过期）同族但更极端。
